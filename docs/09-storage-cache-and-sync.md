# 09 · 存储、缓存与同步

> 状态：提案 · 关联 ADR-0006。目标是可恢复、可清理、账号隔离，而非把官方数据库完整复制到客户端。

## 1. 存储分类与路径

使用 `QStandardPaths` 解析实际路径，不硬编码 `/home/用户名` 或依赖当前工作目录。应用身份应在 M0 冻结；Flatpak 下路径由运行时重定向。

| 数据 | 位置策略 | 生命周期 |
| --- | --- | --- |
| 非敏感设置 | AppConfigLocation，QSettings | 用户主动修改／重置；有 configVersion |
| 安装级状态（设备 ID、协议公钥公开部分） | AppLocalDataLocation 下 `state.sqlite`（已实现） | 跨重启稳定；不随重置设置／清缓存改变，不随 dotfiles 同步 |
| 公共元数据 | AppLocalDataLocation 下 `catalog.sqlite` | 可重建，只含公开信息 |
| 私有音乐库 | AppLocalDataLocation 下 `profiles/<opaque-uuid>/library.sqlite` | 账号专属；guest 有独立 profile |
| 封面／歌词缓存 | CacheLocation；公共和 profile 私有目录分开 | TTL + LRU，可清理 |
| 临时传输文件 | 受控临时目录或下载目标同目录的私有临时文件 | 完成／取消后回收，启动清理孤儿 |
| 授权下载 | 用户选择的目录，或应用管理目录 | 用户拥有明确删除权，不归普通 LRU |
| Cookie／会话秘密 | 系统密钥环 | 到期／登出删除；数据库仅存引用 |
| 日志 | 独立应用状态／数据子目录，轮转 | 初始 7 天或总计 20 MiB，先到者触发淘汰 |

目录尽量按用户私有权限创建；敏感文件权限建议 0600、目录 0700。文件系统权限不能防御同一用户下的恶意程序；数据库未采用额外加密时必须如实说明，不宣称“本地数据全加密”。

## 2. SQLite 访问约束

- 所有读写通过 DatabaseWorker，连接在所属线程内创建、关闭；不跨线程共享连接对象。
- 每个库初始化 `foreign_keys=ON`；启用 WAL 前检查本地文件系统条件，并设置有界 busy timeout（初值 3 s）。
- 用户资料优先可靠性，初始采用 `synchronous=FULL`；若性能测试建议调整，只能经 ADR 审查后区分可重建缓存和关键数据。
- WAL 适合本地磁盘，不把活动数据库放在未经验证的网络文件系统；用户只选择音乐目录，不任意移动运行中的数据库。
- 大批次写入分块，但业务原子单元在同一事务完成；UI 不等待 SQLite 锁。
- 不关闭 foreign key 或使用全库重建解决普通约束错误。
- 单实例避免同 profile 多进程写；锁和 stale lock 恢复见 Linux 集成。

## 3. 数据所有权

| 类别 | 权威来源 | 本地操作 |
| --- | --- | --- |
| 官方目录、推荐、权益、歌单内容 | 官方 API | 保存带更新时间和完整性的快照 |
| 本地队列、显示设置、歌词偏移 | Cirrus 本地 | 事务持久化；无服务端依赖 |
| 喜欢／收藏／远程歌单编辑 | 官方确认态 + 本地待确认意图 | 不能把未确认写入当远程事实 |
| 用户文件 | 用户文件系统 | 默认只读索引；删除需明确选择 |
| 授权下载 | 文件系统 + 当前授权规则 | 文件存在与授权可用分开判断 |

公共库不得保存云盘标题、私人歌单详情、个人历史或账号权限。私有库可以保存公开歌曲元数据的必要快照，避免队列依赖可被淘汰的公共缓存；其内容不再跨 profile 共享。

## 4. 缓存政策

以下初值可在测量后调整；服务端显式缓存限制和账号权限优先。

| 内容 | 初始策略 | 失效规则 |
| --- | --- | --- |
| 公共歌曲／专辑／歌手摘要 | 24 h TTL，可先旧后新 | 手动刷新、重要元数据变化 |
| 搜索结果 | 5 min 内存短缓存 | queryKey／账号上下文变化 |
| 歌单摘要与曲目快照 | 5 min 后刷新，注明完整性 | 写操作确认后立即失效；不完整页不覆盖完整库 |
| 推荐／榜单 | 按服务端周期，缺省最多 1 h 后校验 | 换号、日期／榜单周期改变 |
| 歌词 | 内容 fingerprint + 长 TTL，建议 7 天复查 | 用户刷新／提供方内容变更 |
| 封面 | 尺寸化缓存，初始磁盘总预算 512 MiB | LRU、版本变更、用户清理 |
| 非图片元数据／歌词缓存 | 初始合计预算 128 MiB | TTL + LRU；关键用户记录不算入 |
| 临时播放来源／权限判断 | 不持久化来源 URL；权限短期会话内使用 | 到期、换号、重试、实际服务否定 |
| 账号凭据 | 不进入缓存系统 | 密钥环专门生命周期 |

实现一个 CacheIndex 跟踪大小、最近访问、引用／pin 状态。清理不能删除正在使用的文件、下载临时文件或用户下载。流式音频磁盘缓存首版默认未启用；只有完成受控传输设计后才能设置容量并向用户承诺。

缓存键至少包含数据类别、规范化参数、版本和必要 profile。不能只凭相同 URL 把私人资源误判公共，也不能把整个带签名 URL 当作明文文件名。

## 5. 写同步与冲突处理

### 5.1 正常写流程

1. 读取当前 confirmed snapshot，保存期望状态和 mutationId。
2. 同一实体串行执行；乐观 UI 标记 pending。
3. 官方确认成功后更新 confirmed snapshot；需要时补读。
4. 官方明确拒绝则回滚到最新 confirmed snapshot，不回滚别的已成功操作。
5. 超时／断线导致结果未知时进入 reconciliation；禁止盲重放非幂等命令。

### 5.2 冲突

- 有 revision／ETag：携带条件更新（仅当官方支持），冲突后读新版本。
- 无 revision：使用客户端指纹辅助发现变化，不声称防止所有并发覆盖。
- 喜欢这类 set 状态可在契约允许时收敛到最新意图。
- 歌单整表重排、删除、云盘操作不可自动 last-write-wins；冲突时展示差异或要求刷新重做。
- 部分批次成功保留逐项结果，重新拉取确认；不能把全部回滚按钮当作有跨请求服务端事务。

首版不支持通用离线远程写队列。`pending_mutations` 用于崩溃后识别未完成／未知操作，并非允许所有离线操作自动重放。新增 outbox 时须定义 TTL、用户撤销、账号过期、去重与冲突政策。

## 6. 迁移与备份

每次 schema 变化新增递增迁移，保留 checksum 和应用版本，已发布迁移不可改写。

升级流程：暂停库访问 → 检查磁盘空间 → 建立一致备份 → 事务迁移 → 外键／完整性检查 → 更新版本 → 开放服务。

- 活跃 WAL 数据库不能仅复制 `.sqlite` 主文件作为备份。首版可关闭相关连接、成功 checkpoint／退出 WAL 活动后制作一致快照；或经验证使用 SQLite backup API。
- checkpoint 失败／仍有连接／空间不足即终止迁移，保留原库。
- 事务内失败回滚；不可回滚的外部文件移动采用两阶段记录，恢复任务可重复执行。
- 迁移后保留上一个稳定快照及版本元数据，数量和体积设限。
- 遇到更高 schema 版本，不允许旧程序覆盖写入；提供只读提示或恢复备份的明确流程，不能自动降级丢数据。
- 测试从每个仍支持的旧版本升级、迁移中 kill、损坏页、磁盘满和缺权限。

Qt SQLite 驱动的具体 SQLite 版本由包决定；记录它，不假定系统 `sqlite3` CLI 与运行时驱动完全一致。CLI 只作为开发诊断工具，不作为产品运行依赖。

## 7. 崩溃与文件一致性

文件完成和数据库提交之间不能实现天然跨资源事务，因此采用显式状态：

1. 临时文件下载并校验，DB 标记 Verifying。
2. 同文件系统 rename 到最终受控名称，必要时同步关键文件／目录。
3. 事务写入 asset 索引并标记 Completed。
4. 启动扫描：最终文件存在但任务未完成则校验后补记；任务 Completed 但文件缺失则标记 Missing，绝不假装可播。

清理 orphan 只针对带应用标记的临时文件，并设置保留窗口，不能删除用户目录中“不认识”的音乐。队列快照与当前项在同一事务更新，避免重启时 currentEntryId 指向不存在条目。

## 8. 登出、切号与删除数据

- 登出立刻删除持久凭据、清内存 Cookie／URL、关闭私有展示并递增 epoch。
- 账号库关闭，不允许游客或另一账号读取；默认不删除用户创建的本地记录和下载文件。
- 界面单独提供“清理该账号缓存／历史”和“删除该账号下载文件”，说明范围与不可逆性。
- 清缓存不是退出登录；退出登录也不是擦除文件系统上的全部历史。
- 用户主动“删除此设备全部账号数据”时，删除私有 DB、缓存和密钥环项；对外部下载目录仍需单独确认。
- guest 的本地库不因登录自动上传或并入官方库；如需跨 profile 共享本地索引，必须通过明确用户选择。
- DB 保留并不保证离线授权；每次使用受限资源仍遵守授权契约。

## 9. 备份／导出与磁盘预算

用户导出的是带版本的必要元数据和本地偏好，默认不含凭据、短期媒体 URL及私人绝对路径。导入先校验大小、结构和重复项，再预览合并；不得执行 SQL dump 中的任意语句。

“清理空间”页面分别显示：元数据缓存、封面缓存、临时文件、用户下载和数据库。空间不足先停止新的大任务并提示，不能为了继续播放擅自删用户文件。

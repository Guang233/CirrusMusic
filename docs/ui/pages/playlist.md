# 歌单详情页设计

状态：**已评审**（2026-11-01），**已实现**（§12）。P1–P4 按建议；P5 改为照常显示收藏按钮（§9）。评审时维护者给了网易云和 Apple Music 的歌单／专辑页截图作参考，据此做了几处调整（§11）。

专辑页、每日推荐页沿用同一套版式（§8），本文以歌单为准。

## 1. 这一页做什么

用户从侧边栏的歌单、首页的歌单卡片和榜单、搜索结果进到这里。要做的事按频率排：

1. **放这个歌单**：从头放，或从某一首放。
2. **找到某一首**：歌单可能有几百上千首。
3. **管理**：红心某首、把某首收藏到别的歌单；自己的歌单还要改名、改简介、移除歌曲、调整顺序。

这是桌面上最常用、停留最久的页面，所以按桌面习惯设计：信息密度高，像表格；键盘可以完成所有操作。

## 2. 可用数据与操作

| 内容 | 后端 | 备注 |
| --- | --- | --- |
| 标题、简介、封面、标签、创建者昵称 | `PlaylistDetails` | 创建者只有昵称，没有头像；昵称不能证明是谁的歌单 |
| 歌曲数、播放数、收藏数、评论数、分享数、创建／更新时间 | 同上 | 都可能缺失，缺失时不显示，不显示"0" |
| 歌曲 | 完整 ID 序列 + 分页补详情（每页最多 100 首） | 先有行、后有详情：没到的行显示占位条（`SongListModel.loaded`），滚动到附近再取 |
| 红心 | `SongHeart` | 登录后 |
| 收藏到歌单／从歌单移除 | `PlaylistCollectSongs` | 登录后；移除只对自己的歌单 |
| 改名、改简介、删除歌单、调整歌曲顺序 | 歌单管理写入 | 只对自己的歌单（以音乐库"创建的歌单"为准，服务端仍可能拒绝） |
| 评论 | 评论读取 | 评论页以后单独设计，这里只放入口和数量 |
| 收藏整个歌单 | 目前不可用 | 后端卡在 v2 门禁（[collection-writes.md](../../api/collection-writes.md)），上线前会修好；界面照常做，先用假数据源（P5） |

## 3. 版式

### 3.1 宽（面板 ≥ 840）

```text
┌─ 面板 ───────────────────────────────────────────────────────────────────┐
│                                                                          │
│  ┌──────────┐  歌单                                                       │
│  │          │  深夜通勤                                   ← headlineLarge  │
│  │  封面     │  sample-user · 更新于 10月28日                               │
│  │  200×200 │  适合深夜回家路上听的歌，安静一点，慢一点……  更多              │
│  │          │  [华语] [夜晚] [安静]                         ← 标签纸片       │
│  └──────────┘  9 首 · 播放 12.3 万次 · 收藏 860                              │
│                                                                          │
│  (▶ 播放全部)  (🔖 收藏)  [💬 评论 128]  [⋮]          [🔍 在歌单中查找    ]  │
│                                                                          │
│   #   标题                                  专辑               喜欢  时长  │ ← 列标题，可排序
│  ┌────────────────────────────────────────────────────────────────────┐  │
│  │ 1  ▢ 星屑（Stardust）                    夜航                 ♡  3:53│  │
│  │    ▢ 星屑合唱团                                                       │  │
│  │ ▶  ▢ 落日航线                            落日航线             ♥  3:41│  │ ← 悬停：序号变播放
│  │    ▢ 雾港乐队                                                    ⋮    │  │
│  └────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────┘
```

- **头部**：封面 200 px（`large` 圆角），右边一列：类型标签"歌单"（`labelLarge`，`primary`）、标题（`headlineLarge`；自己的歌单后面跟一个编辑图标按钮，打开"编辑歌单信息"对话框）、创建者 · 更新时间、简介（两行，超出显示"更多"，点开在对话框里看全文）、标签（纸片，点击去发现页的该分类）、数字行（`bodyMedium`，`onSurfaceVariant`）。
- **操作行**：播放全部（Filled）、收藏／已收藏（Tonal，只在别人的歌单上，P5）、评论（Text，带数量）、"更多"菜单（复制链接；自己的歌单另有编辑信息、删除歌单）；最右是常驻的"在歌单中查找"小输入框（36 px 高，见 P2）。没有随机播放按钮（维护者，2026-11-01）：随机是播放顺序，由播放条控制。
- **歌曲表**（见 P1）：列为 序号 / 标题 / 专辑 / 喜欢 / 时长，行高 56。标题格是 40 px 小封面加两行：歌名（译名或别名用 `onSurfaceVariant` 跟在后面）和歌手（每位歌手可点）。窄于一定宽度时专辑列先收起。行是分段列表的样式（`surfaceContainer`，首尾圆角）。
- **序号格**：平时是序号；悬停时换成播放按钮（单击就播放这一首，给鼠标用户一个不用双击的入口）；正在播放的行高亮，序号换成均衡器图标，悬停时换成暂停按钮。行尾的"更多"按钮悬停或有焦点时出现。
- **滚动时**：头部随内容滚走；滚过头部后，面板顶部出现一条 56 px 的紧凑栏（小封面、标题、播放全部），用 `standardFastSpatial` 滑入。列标题吸附在紧凑栏下方，长歌单里始终知道每列是什么。

### 3.2 窄（面板 < 840）

- 封面 140 px，头部信息在封面右侧缩为：标题、创建者、数字行；简介和标签移到封面下方整行。
- 歌曲表只留 序号／标题／时长；红心进行的"更多"菜单。
- 操作行的"评论"收进"更多"菜单；"在歌单中查找"缩成图标按钮，点开展开成输入框。

## 4. 视觉方向

这一页的主角是**歌曲表**，不是头部。版式克制，力气花在表格的手感上：

- 对齐的列、等宽的序号和时长数字：MiSans 的数字默认不等宽（"1" 403 单位宽，"0" 634），用字体的 `tnum` 特性（Qt 6.6 起 `font.features: { "tnum": 1 }`）切成等宽再靠右对齐，滚动时数字列不抖。
- 悬停整行的状态层；行尾悬停时才出现"更多"按钮，红心常驻，已红心用 `primary` 实心。
- 不做头部的大面积取色背景（见 P4 的另一选项），头部就在面板的 `surface` 上，封面本身提供颜色。

字体：标题 `headlineLarge`，表格正文 `bodyMedium`，列标题 `labelMedium`（`onSurfaceVariant`），序号和时长 `labelLarge` 靠右。

## 5. 交互

### 5.1 鼠标

| 操作 | 结果 |
| --- | --- |
| 双击行 | 以整个歌单（按当前排序）为队列，从这首开始播放。单击只选中（桌面习惯；见 P3） |
| 行上的红心 | 红心／取消红心 |
| 右键行、行尾"更多" | 下一首播放、收藏到歌单…、红心、查看专辑、查看歌手、从歌单移除（自己的歌单）、复制链接 |
| 悬停行的序号格出现的播放按钮 | 播放这一首（同双击） |
| 点列标题（标题、专辑、时长） | 按该列排序（升序 → 降序 → 恢复歌单原顺序）；排序只影响显示和"播放全部"的顺序，不改歌单 |
| 行里的歌手名 | 打开歌手页 |
| 调整歌曲顺序 | 在单独的页面里做（§13），歌单页上不能拖动，避免误触 |
| 点标签 | 去发现页的该分类 |

### 5.2 键盘

| 按键 | 结果 |
| --- | --- |
| ↑／↓、PageUp／PageDown、Home／End | 在行之间移动焦点（焦点环包住整行） |
| Enter | 播放焦点所在的行 |
| 菜单键、Shift+F10 | 打开该行的菜单 |
| Ctrl+A、Shift+↑／↓、Ctrl+单击、Shift+单击 | 多选（P3） |
| Delete | 从歌单移除选中的歌（自己的歌单，先确认） |
| 输入字符（焦点在表格上） | 焦点移到"在歌单中查找"并填入（P2） |
| Ctrl+F | 聚焦"在歌单中查找"（浏览器习惯：Ctrl+F 找页面内的东西）；Ctrl+K 仍是全局搜索。没有页内查找的页面上 Ctrl+F 照旧聚焦全局搜索 |
| 查找框里 Esc | 清空查找；再按把焦点还给表格 |
| Tab | 头部按钮 → 操作行 → 表格（表格整体是一个 Tab 停靠点，内部用方向键） |

## 6. 状态

| 状态 | 表现 |
| --- | --- |
| 首次加载 | 头部骨架（封面方块、标题与文字条、操作行的按钮和查找框）＋ 列标题 ＋ 8 行行骨架，位置与加载后的内容一致（`SongTableSkeleton` 用表格自己的列宽）；150 ms 内到达不显示 |
| 行的详情未到 | 行先在，序号照常显示，标题／歌手处是占位条；滚动到附近时按页补齐 |
| 部分歌曲取不到 | 那几行显示"歌曲信息暂时无法获取"，可以跳过；表格上方一条提示"有 N 首歌暂时无法获取信息" |
| 空歌单 | 头部照常；表格位置："这个歌单还没有歌"；自己的歌单加一句"在歌曲的菜单里选择「收藏到歌单」就能加进来" |
| 失败 | 整页错误 + 重试（`StateMessage`） |
| 私密歌单、已删除 | 服务端拒绝 → "这个歌单不存在或无法访问" |
| 未登录 | 公开歌单照常看和播放；红心、收藏到歌单时打开登录对话框 |
| 歌曲不可播放 | 播放失败后该行变灰（`unavailable`），双击给出原因的提示 |

## 7. 动效

- 头部到紧凑栏：滚动驱动（不是时间驱动），封面缩小、标题移动，跟手、可逆。
- 排序：行用 `standardFastSpatial` 移到新位置（行数多于约 200 时直接切换，避免卡顿）。
- 红心：图标填充 + 轻微缩放回弹（`fastSpatial`）。
- 减少动态效果时全部直接切换。

## 8. 专辑页与每日推荐页沿用

细化设计见 [album-daily.md](album-daily.md)（以那里为准；两页都不能排序，保留查找）。

| 页面 | 头部的不同 | 表格的不同 |
| --- | --- | --- |
| 专辑 | 类型"专辑"、歌手（可点）、发行日期、唱片公司；操作行有"收藏专辑"（`AlbumSubscribe` 可用） | 不显示封面和专辑列；有碟号时分组 |

## 10. 实现时的展示层改动

- `PlaylistPageModel` 增加：`tags`、`playCount`、`subscriberCount`、`commentCount`、`updatedAt`、`trackCount`、`own`（在音乐库"创建的歌单"里）。
- 歌曲按页补详情：接入已有的 `loaded` 机制，滚动到附近时请求那一页。
- 排序与查找在展示层做（一个代理模型），不改动原顺序；"播放全部"按当前显示顺序取 key。
- 多选：选中集合放在页面（QML）里，批量操作调用数据源。
- 写操作（红心、收藏到歌单、移除、改名、删除、排序）走新的数据源接口和假实现，结果失败时撤回界面上的改动并提示。

## 11. 参考截图后的调整（2026-11-01）

维护者给了网易云（歌单页）和 Apple Music（专辑页）的截图。

| 采纳 | 来源 | 改了什么 |
| --- | --- | --- |
| 歌手并进标题格第二行 | 网易云 | 原来歌手单独一列。小封面配两行文字（歌名、歌手）是带封面的歌单表格的通行做法（网易云、Spotify），专辑列因此更宽；窄窗口也不用换一种行 |
| 常驻的查找框 | 两者 | 原来是按钮点开。网易云放在标签行右侧、Apple Music 放在右上角，都是一直在那里；改为操作行最右的小输入框，并接上 Ctrl+F |
| 悬停时序号变播放按钮，正在播放的行悬停变暂停 | Apple Music | 单击仍是选中（P3），但鼠标用户有了不用双击的播放入口 |
| 自己的歌单在标题后放编辑按钮 | 网易云 | 原来只在"更多"菜单里 |

没有采纳：

- 网易云的"歌曲／评论／收藏者"标签：评论页以后单独设计，这里保持评论按钮；收藏者列表后端没有接口。
- 封面上的播放数、创建者头像：后端只有昵称；播放数已在数字行里。
- Apple Music 的超大封面（约 400 px）和强调色的歌手名：这一页的主角是表格（§4），封面保持 200。

## 12. 实现进度

分三步：

1. **页面本体（已完成，2026-11-01）**：头部（宽／窄两种排法、简介"更多"对话框、标签、数字行）、操作行（播放全部、收藏／已收藏、评论入口、查找框）、可排序的歌曲表（`SongTable`、`SortedSongsModel`）、单击选中／Ctrl／Shift 多选、双击和悬停播放按钮播放、键盘（方向键、PageUp／PageDown、Home／End、Enter、Ctrl+A、Ctrl+Space、菜单键、Esc）、行菜单（播放／播放选中的 N 首、查看专辑、查看歌手）、滚动后的紧凑栏和吸顶列标题、页内查找（Ctrl+F、在表格上直接打字）、空歌单和没有查找结果的提示。收藏歌单接了假数据源（`LibrarySource::setPlaylistSubscribed`），成功后侧边栏刷新，失败撤回并用提示条（`Snackbar`）说明。
   之后的修改（维护者反馈）：去掉随机播放；加评论入口；加载骨架原来沿用旧原型的 `ListSkeleton`（160 封面、72 高的行、没有列标题和专辑列、不居中），与新版式对不上，改为 `SongTableSkeleton`。
2. **红心与写操作（已完成，2026-11-01）**：
   - 喜欢列（心形常驻，已喜欢用实心主色；未登录时点击打开登录对话框），行菜单里也有喜欢／取消喜欢。全局状态 `App.library`，写入先改界面，失败撤回并用提示条说明。
   - 收藏到歌单：行菜单"收藏到歌单…"（选中多首时是"收藏选中的 N 首到歌单…"）打开外壳里的选择对话框（`AddToPlaylistDialog`），列出自己创建的歌单；列表是一个 Tab 停靠点，↑／↓ 选、Enter 确定。顶上一项"新建歌单"（维护者 2026-11-09 要求）：点开后对话框换成标题输入框，"新建并收藏"先建歌单、再把歌加进去（`Library::createPlaylistWith`），两步各自用提示条报告结果；它和列表之间可用 ↓／↑ 切换。列表项改为 MD3E 的分段圆角样式（`segmented`），悬停、选中的区域是圆角的。
   - 自己的歌单：从歌单移除（行菜单或 Delete，先确认）、标题旁的编辑按钮和操作行的"更多"菜单（编辑歌单信息、删除歌单；删除先确认，成功后后退）。调整顺序先做在歌单页上（拖动、Alt+↑／↓），维护者反馈插入线错位、容易误触后撤下，改为单独的页面（§13，待评审）。
3. **大歌单按页补详情（已完成，2026-11-01）**：歌单先给出全部歌曲 key 和一部分详情，其余行显示占位条。表格报告屏幕上的行（`firstVisibleRow`／`lastVisibleRow`），页面请求它们前后 20 行所在的整批（每批最多 100 首，`CatalogSource::songDetails`，对应后端一次 `/api/v3/song/detail` 请求）。同一时间只有一个请求在途，其余排队，屏幕上的行排在前面；失败时清空队列，下次滚动到时再请求。排序或查找时取回全部详情（两者都需要完整信息）。服务端没有详情的歌：行变灰显示"歌曲信息暂时无法获取"，播放时跳过，表格上方提示"有 N 首歌暂时无法获取信息"。假数据加了一个 600 首的"很长的歌单"（在收藏的歌单里），只带前 100 首的详情，每 97 首有一首取不到。

实现时的偏差：

- 标签暂时搜索该标签（发现页的分类还没有设计）。
- 播放全部不改变播放顺序。随机播放按钮按维护者要求去掉了（2026-11-01）。
- 评论入口先显示数量，点击用提示条说明评论页还在设计中（评论页以后单独设计）。评论页已实现（[comments.md](comments.md)），按钮现在打开它。
- 复制链接还没做：数据源没有给出分享链接，等接后端时一起加。
- 简介用单行输入框编辑（还没有多行输入控件）。
- 排序或查找要取回全部详情：按批依次请求（1000 首是 10 次请求，一次一个），不并发（维护者：尽量不要发大量请求）。
- 写入请求跟着页面走：页面在请求返回前被关掉时，请求会被取消。
- 滚动：试过自己处理鼠标滚轮（一格 120 px、缓动），维护者觉得忽快忽慢，按维护者意见恢复 Qt 默认的滚轮（一格 72 px）。所有页面的滚动视图改为 `DragAndOvershootBounds`：滚轮、触控板滚到两端会越过一点再弹回（实测约 36 px）。紧凑栏和吸顶列标题让开右侧 12 px，不再盖住滚动条。
- 表格的当前行不用 `ListView.currentIndex`：列表是焦点域，会把焦点交给当前行，抢走头部查找框的焦点。表格自己记当前行，焦点留在列表本身。

## 13. 调整歌曲顺序（已评审、已实现，2026-11-01）

维护者反馈：在歌单页上拖动排序容易误触，插入线也对不准（DragHandler 越过拖动阈值后才开始计位移，算出的位置比指针慢一个阈值的距离）；排序放到单独的页面，并提供按歌名、歌手等的快速排序。

### 13.1 入口与版式

自己的歌单，操作行"更多"菜单 → "调整歌曲顺序"，压栈打开（`PlaylistOrderPage`）。

```text
┌─ 面板 ───────────────────────────────────────────────────────────────────┐
│  调整歌曲顺序                           (⇅ 快速排序 ▾)  [取消]  (保存)     │
│  深夜通勤 · 9 首                                                          │
│                                                                          │
│  ┌────────────────────────────────────────────────────────────────────┐  │
│  │ ⠿   1  ▢ 星屑                 星屑合唱团        夜航           3:53  │  │
│  │ ⠿   2  ▢ 落日航线             雾港乐队          落日航线       3:41  │  │ ← 48 高的紧凑行
│  └────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────┘
```

- 标题行：标题（`headlineSmall`）和"歌单名 · 歌曲数"（快速排序在等歌曲信息时换成"正在取回歌曲信息，还剩 N 首…"）；右侧"快速排序"（Tonal，带下拉箭头）、"取消"（Text）、"保存"（Filled，没有改动时不可用）。标题行不随列表滚动。
- 快速排序是一个菜单（维护者：不用一排按钮）：按歌名、按歌手、按专辑、按时长（短的在前）、倒序。文字按系统语言的排序规则（中文按拼音），取不到信息的歌排在最后，相同的保持原来的先后。要降序就再选"倒序"。没有"恢复原顺序"（维护者：排错了不保存、重新打开即可）。
- 列表：48 高的紧凑行（拖动把手、序号、32 px 封面、歌名、歌手、专辑、时长），没有喜欢、菜单、播放。

### 13.2 操作

| 操作 | 结果 |
| --- | --- |
| 按住行首的把手拖动 | 这一行浮起跟着指针，插入线标出放下的位置（按指针的实际位置计算），靠近上下边缘时列表自动滚动，松手移动；选中的其他行留在原处变淡，一起移过去。只有把手能拖，点行的其他地方是选中 |
| 单击、Ctrl／Shift+单击 | 选中、多选（和歌单页一致） |
| ↑／↓、Shift+↑／↓、Ctrl+A、Ctrl+Space | 移动当前行、扩选、全选、切换选中 |
| Alt+↑／↓ | 把选中的歌作为一组上移／下移一位 |
| Alt+Home／Alt+End、右键、菜单键 | 移到最前／最后 |
| Ctrl+S | 保存 |
| Esc（没有选中时）、后退、取消 | 没有改动时直接离开；有改动时先问"放弃对歌曲顺序的修改？"（放弃／继续调整） |

### 13.3 保存与请求

- 所有改动只在本页，点"保存"时发**一次**请求（`reorderPlaylist`，带完整的新顺序）。保存成功回到歌单页（歌单页和侧边栏刷新）并提示"已保存歌曲顺序"；失败留在本页，提示原因，改动保留。离开这一页不留"前进"记录。
- 大歌单：拖动和移动不需要歌曲信息（没到的行显示占位条，滚到附近按批补）；快速排序需要全部信息，先按批依次取回（一次一个请求）再排序。

### 13.4 决定（维护者，2026-11-01）

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| R1 | 快速排序的选项 | 歌名、歌手、专辑、时长、倒序；不要"恢复原顺序"。做成菜单，不是一排按钮 |
| R2 | 保存方式 | 点"保存"一次提交 |
| R3 | 多选一起移动 | 要 |

# 歌单详情页设计

状态：**已评审**（2026-11-01）。P1–P4 按建议，P5 暂缓（§9）。评审时维护者给了网易云和 Apple Music 的歌单／专辑页截图作参考，据此做了几处调整（§11）。

专辑页、每日推荐页沿用同一套版式（§8），本文以歌单为准。

## 1. 这一页做什么

用户从侧边栏的歌单、首页的歌单卡片和榜单、搜索结果进到这里。要做的事按频率排：

1. **放这个歌单**：从头放，或从某一首放。
2. **找到某一首**：歌单可能有几百上千首。
3. **管理**：红心某首、把某首收藏到别的歌单；自己的歌单还要改名、改简介、移除歌曲、调整顺序。

这是桌面上最常用、停留最久的页面，所以按桌面习惯设计：信息密度高，像表格；键盘可以完成所有操作。

## 2. 可用数据与操作

| 内容 | 后端 | 备注 |
| --- | --- | --- |
| 标题、简介、封面、标签、创建者昵称 | `PlaylistDetails` | 创建者只有昵称，没有头像；昵称不能证明是谁的歌单 |
| 歌曲数、播放数、收藏数、评论数、分享数、创建／更新时间 | 同上 | 都可能缺失，缺失时不显示，不显示"0" |
| 歌曲 | 完整 ID 序列 + 分页补详情（每页最多 100 首） | 先有行、后有详情：没到的行显示占位条（`SongListModel.loaded`），滚动到附近再取 |
| 红心 | `SongHeart` | 登录后 |
| 收藏到歌单／从歌单移除 | `PlaylistCollectSongs` | 登录后；移除只对自己的歌单 |
| 改名、改简介、删除歌单、调整歌曲顺序 | 歌单管理写入 | 只对自己的歌单（以音乐库"创建的歌单"为准，服务端仍可能拒绝） |
| 评论 | 评论读取 | 评论页以后单独设计，这里只放入口和数量 |
| **收藏整个歌单** | **不可用** | 后端卡在 v2 门禁，暂缓（[collection-writes.md](../../api/collection-writes.md)），见 P5 |

## 3. 版式

### 3.1 宽（面板 ≥ 840）

```text
┌─ 面板 ───────────────────────────────────────────────────────────────────┐
│                                                                          │
│  ┌──────────┐  歌单                                                       │
│  │          │  深夜通勤                                   ← headlineLarge  │
│  │  封面     │  sample-user · 更新于 10月28日                               │
│  │  200×200 │  适合深夜回家路上听的歌，安静一点，慢一点……  更多              │
│  │          │  [华语] [夜晚] [安静]                         ← 标签纸片       │
│  └──────────┘  9 首 · 播放 12.3 万次 · 收藏 860                              │
│                                                                          │
│  (▶ 播放全部)  (⤮ 随机播放)  [💬 评论 128]  [⋮]     [🔍 在歌单中查找    ]  │
│                                                                          │
│   #   标题                                  专辑               喜欢  时长  │ ← 列标题，可排序
│  ┌────────────────────────────────────────────────────────────────────┐  │
│  │ 1  ▢ 星屑（Stardust）                    夜航                 ♡  3:53│  │
│  │    ▢ 星屑合唱团                                                       │  │
│  │ ▶  ▢ 落日航线                            落日航线             ♥  3:41│  │ ← 悬停：序号变播放
│  │    ▢ 雾港乐队                                                    ⋮    │  │
│  └────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────┘
```

- **头部**：封面 200 px（`large` 圆角），右边一列：类型标签"歌单"（`labelLarge`，`primary`）、标题（`headlineLarge`；自己的歌单后面跟一个编辑图标按钮，打开"编辑歌单信息"对话框）、创建者 · 更新时间、简介（两行，超出显示"更多"，点开在对话框里看全文）、标签（纸片，点击去发现页的该分类）、数字行（`bodyMedium`，`onSurfaceVariant`）。
- **操作行**：播放全部（Filled）、随机播放（Tonal）、评论（Text，带数量）、"更多"菜单（复制链接；自己的歌单另有编辑信息、删除歌单）；最右是常驻的"在歌单中查找"小输入框（36 px 高，见 P2）。收藏歌单按钮的位置留在随机播放之后（P5）。
- **歌曲表**（见 P1）：列为 序号 / 标题 / 专辑 / 喜欢 / 时长，行高 56。标题格是 40 px 小封面加两行：歌名（译名或别名用 `onSurfaceVariant` 跟在后面）和歌手（每位歌手可点）。窄于一定宽度时专辑列先收起。行是分段列表的样式（`surfaceContainer`，首尾圆角）。
- **序号格**：平时是序号；悬停时换成播放按钮（单击就播放这一首，给鼠标用户一个不用双击的入口）；正在播放的行高亮，序号换成均衡器图标，悬停时换成暂停按钮。行尾的"更多"按钮悬停或有焦点时出现。
- **滚动时**：头部随内容滚走；滚过头部后，面板顶部出现一条 56 px 的紧凑栏（小封面、标题、播放全部），用 `standardFastSpatial` 滑入。列标题吸附在紧凑栏下方，长歌单里始终知道每列是什么。

### 3.2 窄（面板 < 840）

- 封面 140 px，头部信息在封面右侧缩为：标题、创建者、数字行；简介和标签移到封面下方整行。
- 歌曲表只留 序号／标题／时长；红心进行的"更多"菜单。
- 操作行的"评论"收进"更多"菜单；"在歌单中查找"缩成图标按钮，点开展开成输入框。

## 4. 视觉方向

这一页的主角是**歌曲表**，不是头部。版式克制，力气花在表格的手感上：

- 对齐的列、等宽的序号和时长数字：MiSans 的数字默认不等宽（"1" 403 单位宽，"0" 634），用字体的 `tnum` 特性（Qt 6.6 起 `font.features: { "tnum": 1 }`）切成等宽再靠右对齐，滚动时数字列不抖。
- 悬停整行的状态层；行尾悬停时才出现"更多"按钮，红心常驻，已红心用 `primary` 实心。
- 不做头部的大面积取色背景（见 P4 的另一选项），头部就在面板的 `surface` 上，封面本身提供颜色。

字体：标题 `headlineLarge`，表格正文 `bodyMedium`，列标题 `labelMedium`（`onSurfaceVariant`），序号和时长 `labelLarge` 靠右。

## 5. 交互

### 5.1 鼠标

| 操作 | 结果 |
| --- | --- |
| 双击行 | 以整个歌单（按当前排序）为队列，从这首开始播放。单击只选中（桌面习惯；见 P3） |
| 行上的红心 | 红心／取消红心 |
| 右键行、行尾"更多" | 下一首播放、收藏到歌单…、红心、查看专辑、查看歌手、从歌单移除（自己的歌单）、复制链接 |
| 悬停行的序号格出现的播放按钮 | 播放这一首（同双击） |
| 点列标题（标题、专辑、时长） | 按该列排序（升序 → 降序 → 恢复歌单原顺序）；排序只影响显示和"播放全部"的顺序，不改歌单 |
| 行里的歌手名 | 打开歌手页 |
| 拖动行（自己的歌单，原顺序下） | 调整歌曲顺序 |
| 点标签 | 去发现页的该分类 |

### 5.2 键盘

| 按键 | 结果 |
| --- | --- |
| ↑／↓、PageUp／PageDown、Home／End | 在行之间移动焦点（焦点环包住整行） |
| Enter | 播放焦点所在的行 |
| 菜单键、Shift+F10 | 打开该行的菜单 |
| Ctrl+A、Shift+↑／↓、Ctrl+单击、Shift+单击 | 多选（P3） |
| Delete | 从歌单移除选中的歌（自己的歌单，先确认） |
| 输入字符（焦点在表格上） | 焦点移到"在歌单中查找"并填入（P2） |
| Ctrl+F | 聚焦"在歌单中查找"（浏览器习惯：Ctrl+F 找页面内的东西）；Ctrl+K 仍是全局搜索。没有页内查找的页面上 Ctrl+F 照旧聚焦全局搜索 |
| 查找框里 Esc | 清空查找；再按把焦点还给表格 |
| Tab | 头部按钮 → 操作行 → 表格（表格整体是一个 Tab 停靠点，内部用方向键） |

## 6. 状态

| 状态 | 表现 |
| --- | --- |
| 首次加载 | 头部骨架（封面方块、三条文字）＋ 8 行行骨架；150 ms 内到达不显示 |
| 行的详情未到 | 行先在，序号照常显示，标题／歌手处是占位条；滚动到附近时按页补齐 |
| 部分歌曲取不到 | 那几行显示"歌曲信息暂时无法获取"，可以跳过；表格上方一条提示"有 N 首歌暂时无法获取信息" |
| 空歌单 | 头部照常；表格位置："这个歌单还没有歌"；自己的歌单加一句"在歌曲的菜单里选择「收藏到歌单」就能加进来" |
| 失败 | 整页错误 + 重试（`StateMessage`） |
| 私密歌单、已删除 | 服务端拒绝 → "这个歌单不存在或无法访问" |
| 未登录 | 公开歌单照常看和播放；红心、收藏到歌单时打开登录对话框 |
| 歌曲不可播放 | 播放失败后该行变灰（`unavailable`），双击给出原因的提示 |

## 7. 动效

- 头部到紧凑栏：滚动驱动（不是时间驱动），封面缩小、标题移动，跟手、可逆。
- 排序：行用 `standardFastSpatial` 移到新位置（行数多于约 200 时直接切换，避免卡顿）。
- 红心：图标填充 + 轻微缩放回弹（`fastSpatial`）。
- 减少动态效果时全部直接切换。

## 8. 专辑页与每日推荐页沿用

| 页面 | 头部的不同 | 表格的不同 |
| --- | --- | --- |
| 专辑 | 类型"专辑"、歌手（可点）、发行日期、唱片公司；操作行有"收藏专辑"（`AlbumSubscribe` 可用） | 不显示封面和专辑列；有碟号时分组 |
| 每日推荐 | 封面换成首页"今日"的日期数字；没有创建者、标签 | 歌手后面加一列推荐理由（窄窗口不显示） |

## 9. 需要决定

| 编号 | 问题 | 建议 |
| --- | --- | --- |
| P1 | 歌曲列表在宽窗口用表格式的列（序号／标题／歌手／专辑／红心／时长，可排序），还是保持现在的两行卡片式行？ | 表格式。桌面上信息一行读完，列对齐便于扫读，网易云桌面版也是这样。**已定：表格式**（歌手后来并进标题格的第二行，§11） |
| P2 | 是否做"在歌单中查找"（只过滤本歌单，不走全局搜索）？ | 做。上千首的歌单只能靠它；与顶栏的全局搜索分开，Ctrl+K 仍是全局。**已定：做** |
| P3 | 单击选中、双击播放，并支持多选和批量操作？还是单击就播放？ | 单击选中、双击播放、支持多选。桌面惯例，也让键盘多选有意义。批量操作先做"下一首播放、收藏到歌单、从歌单移除"。**已定：按建议** |
| P4 | 头部用封面取色做大面积背景（像 Apple Music 的专辑页），还是保持在面板底色上？ | 保持在面板底色上。取色背景要为每页单独算一套配色，而且和"不靠大块颜色分层"的方向不一致；封面本身已经有颜色。**已定：面板底色** |
| P5 | "收藏歌单"按钮：后端不可用期间隐藏，还是显示为禁用并说明原因？ | 隐藏。禁用按钮会让人以为是自己的问题；后端可用后再加。**暂缓**：正式上线时后端一定已修好，所以按钮会有，位置留在操作行随机播放之后（Tonal，收藏后变"已收藏"）；后端接口可用时再实现，在那之前不显示 |

## 10. 实现时的展示层改动

- `PlaylistPageModel` 增加：`tags`、`playCount`、`subscriberCount`、`commentCount`、`updatedAt`、`trackCount`、`own`（在音乐库"创建的歌单"里）。
- 歌曲按页补详情：接入已有的 `loaded` 机制，滚动到附近时请求那一页。
- 排序与查找在展示层做（一个代理模型），不改动原顺序；"播放全部"按当前显示顺序取 key。
- 多选：选中集合放在页面（QML）里，批量操作调用数据源。
- 写操作（红心、收藏到歌单、移除、改名、删除、排序）走新的数据源接口和假实现，结果失败时撤回界面上的改动并提示。

## 11. 参考截图后的调整（2026-11-01）

维护者给了网易云（歌单页）和 Apple Music（专辑页）的截图。

| 采纳 | 来源 | 改了什么 |
| --- | --- | --- |
| 歌手并进标题格第二行 | 网易云 | 原来歌手单独一列。小封面配两行文字（歌名、歌手）是带封面的歌单表格的通行做法（网易云、Spotify），专辑列因此更宽；窄窗口也不用换一种行 |
| 常驻的查找框 | 两者 | 原来是按钮点开。网易云放在标签行右侧、Apple Music 放在右上角，都是一直在那里；改为操作行最右的小输入框，并接上 Ctrl+F |
| 悬停时序号变播放按钮，正在播放的行悬停变暂停 | Apple Music | 单击仍是选中（P3），但鼠标用户有了不用双击的播放入口 |
| 自己的歌单在标题后放编辑按钮 | 网易云 | 原来只在"更多"菜单里 |

没有采纳：

- 网易云的"歌曲／评论／收藏者"标签：评论页以后单独设计，这里保持评论按钮；收藏者列表后端没有接口。
- 封面上的播放数、创建者头像：后端只有昵称；播放数已在数字行里。
- Apple Music 的超大封面（约 400 px）和强调色的歌手名：这一页的主角是表格（§4），封面保持 200。

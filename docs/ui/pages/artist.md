# 歌手页设计（已评审，2026-11-02）

**维护者已定**：AR1–AR4 按建议；MV 先搁置，音乐功能上线后再说。

和歌单、专辑页同一个家族（[playlist.md](playlist.md)、[album-daily.md](album-daily.md)）：头部随内容滚走、操作行、桌面表格、滚走后顶部出现紧凑条。不同在于歌手有几类内容，用标签页分开。参考了维护者给的网易云歌手页截图（§6）。

## 1. 后端能给什么

| 内容 | 接口 | 说明 |
| --- | --- | --- |
| 名字、别名／译名、头像、简介、单曲数、专辑数 | 歌手详情 | 数量可能缺 |
| 分段介绍（标题＋正文，纯文本） | 歌手介绍 | 即网易云的"歌手详情" |
| 热门歌曲 | 热门 50 | 只有前 50 首 |
| 全部歌曲 | 歌手歌曲，分页 | 可按热度或发行时间排 |
| 专辑 | 歌手专辑，分页 | |
| 关注／取消关注 | 歌手订阅 | 需要登录；是否已关注从"关注的歌手"列表得知 |
| 相似歌手 | 相似歌手 | 后端实网试读时被拒绝过一次，可能要登录；失败时按失败显示 |
| MV | 没有 | 也没有视频播放，见 §5 |

## 2. 版式

```
╭────────╮   歌手
│  头像  │   MyGO!!!!!                                   ← headlineLarge
│  圆形  │   マイゴ / 迷子                                ← 别名、译名，" / " 分隔
│  200   │   单曲 86 · 专辑 40
╰────────╯   一行简介……                         更多     ← "更多"切到"详情"标签
[▶ 播放热门歌曲] [＋ 关注]
 歌曲   专辑 40   详情   相似歌手                         ← 标签
──────────────────────────────────────────
 （标签内容）
```

- **头部**
  - 头像是圆形（歌手在全应用都是圆形，与方形的专辑、歌单区分），宽窗口 200、窄窗口 140；没有头像时用占位图标 `person`。
  - 类型行"歌手"；名字；别名和译名一行；数量行"单曲 N · 专辑 N"（缺哪项省哪项）。
  - 简介一行，超出时"更多"切到"详情"标签（不另开对话框：详情标签里有完整内容）。
- **操作行**：播放热门歌曲（Filled，播放热门 50，不管当前在哪个标签）、关注／已关注（Tonal，图标 `person_add`／`how_to_reg`；未登录时点击打开登录）。歌手没有评论。
- **标签**：歌曲、专辑（带数量）、详情、相似歌手。键盘：标签栏是一个 Tab 停留点，←／→ 切换；Ctrl+PageUp／PageDown 在页面任意处切换。
- **滚动**：头部滚走后，顶部出现紧凑条（小圆头像、名字、播放按钮），**标签栏固定在紧凑条下**；歌曲标签的列标题再固定在标签栏下。切换标签时，如果头部已经滚走，新标签从内容顶部开始显示（头部保持滚走），否则保持原位置。

## 3. 各标签

### 3.1 歌曲

- 表格与歌单页相同（序号、封面＋标题＋歌手、专辑、喜欢、时长，悬停播放、多选、键盘、行菜单），列标题不可点。
- 表格上方右侧是"最热／最新"两段的切换（ConnectedButtonGroup，小号），默认最热；切换后从头加载。
- 分页：滚到接近底部时加载下一页（每页 100），底部是加载更多的状态行（`LoadMoreFooter`）。
- 双击或悬停播放某一行时，播放已加载的歌、从这一行开始（AR2）。

### 3.2 专辑

- 专辑卡片网格（`CollectionGrid`，与首页"新碟上架"同样的卡片：封面、标题、"年份 · N 首"），后端顺序（一般是新的在前），滚到底分页加载。
- 点卡片进专辑页（卡片目前没有直接播放的按钮，与首页一致）。

### 3.3 详情

- 先是简介全文，再逐段显示介绍（段落标题用 titleMedium，正文 bodyLarge，行宽不超过 720，便于阅读）。
- 文字可以选择复制（只读文本，不是链接）。后端说明正文是不受信任的纯文本：按纯文本显示，不解析 HTML。
- 没有介绍时："暂时没有这位歌手的介绍"。

### 3.4 相似歌手

- 圆形头像卡片网格（与搜索结果里的歌手卡片相同），点击进对应歌手页。
- 未登录时显示登录提示（如果后端确实要求登录）；失败时显示失败状态和重试。

## 4. 状态

- 加载：骨架按头部（圆形头像）和表格排版；标签内容各自有加载状态（专辑网格、详情段落用对应骨架）。
- 歌手不存在或加载失败：整页失败状态。
- 某个标签失败只影响该标签，显示失败和重试。

## 5. 不做的

- **MV 标签**：后端没有 MV 接口，客户端也没有视频播放。MV 是一个独立的大功能（列表、播放器、清晰度），以后单独设计。
- **页面内查找**：歌曲是分页加载的，查找只能找已加载的部分，容易误导；要找某首歌用全局搜索（AR3）。

## 8. 实现时的改动（评审后）

- 展示层：`ArtistInfo` 加 `aliases`、`followed`；`CatalogSource` 加 `artistTopSongs`、`artistSongs(order, page)`、`artistAlbums(page)`、`artistIntroduction`、`similarArtists`；`LibrarySource` 加 `setArtistFollowed`；`ArtistPageModel` 改为头部＋各标签的子模型（歌曲分页、专辑分页、介绍、相似歌手各自加载、各有状态）；假数据补别名、介绍段落和相似歌手。
- 组件：`SongCollectionPage` 加可选的标签栏（固定在紧凑条下）和按标签切换的内容；歌曲表格支持分页底部（`LoadMoreFooter`）；`CoverArt` 圆形头像已支持。
- 图标：`person_add`、`how_to_reg` 加入 `symbols.txt` 后用 `prepare_fonts.py` 重新生成。

## 9. 实现进度（2026-11-02）

已按本文实现，与 §8 的差别：

- 四个标签共用一个滚动列表：`SongCollectionPage` 加了 `tabsContent`（标签行，头部一份、固定在紧凑条下一份）、`bodyContent`／`showBody`（非歌曲内容放在列表头部里）、`showSongs`、`footerContent`、`findable`、`playText`／`playSource`、`roundCover`；紧凑条改为按操作行的位置出现（头部里有长内容时也对）。`SongTable` 加 `showColumnTitles`、`footerContent`。
- 展示层：`ArtistPageModel`（头部、热门歌曲、关注）带四个子模型：`ArtistSongsModel`（分页，每页 100，`byTime`）、`ArtistAlbumsModel`（分页，每页 30）、`ArtistIntroductionModel`、`SimilarArtistsModel`，各自在标签第一次显示时加载、各有状态。`CatalogSource` 加 `artistSongs`、`artistAlbums`、`artistIntroduction`、`similarArtists`（`artist()` 返回头部和热门 50），`LibrarySource` 加 `setArtistFollowed`。
- 假数据：第一个示例歌手有 230 首歌（重复的示例歌，检查分页）；简介和两段介绍为生成文字，最后一个示例歌手没有介绍；相似歌手要登录。
- 切换标签时如果标签栏已固定，新标签从内容顶部开始；内容不够长（如相似歌手）时列表会回到能滚到的位置，头部重新露出。
- 验证：构建、qmllint、clang-format；离屏截图检查了歌曲标签（宽、窄、滚到底分三页加载完 230 首、固定的标签栏和列标题）、专辑、详情、相似歌手（登录与未登录）、Ctrl+PageUp／PageDown 切换。

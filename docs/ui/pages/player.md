# 播放页设计（设计稿，待评审，2026-11-04）

播放页是整个应用最重要的一页，风格接近 Apple Music（README §2.1）。维护者提出的要求：

- **沉浸感**：背景动态流光、更有立体感的封面、自动隐藏控件、铺满整个窗口（包括顶栏）。
- **高度可自定义**，尤其是歌词。
- **日语音译以注音的样式写在汉字上方**。对齐算法等到实现时再讨论（§6.4）。
- 滚动歌词和逐字歌词要单独设计。

本文的各项决定编号为 P1–P12，汇总在 §11，等维护者确认。和外壳的边界沿用 README §2.3：菜单、对话框、提示条用 MD3E 控件，套用从封面派生的深色配色；去歌手页、专辑页、评论页时先退出播放页。参考对象只取 Apple Music 的体验，AMLL、SPlayer 等是 AGPL 项目，代码一律不复制（[references.md §4](../references.md)）。

## 1. 结构与视图

播放页是盖在外壳上面的一层，打开时铺满整个窗口（P5）。内容分三个视图（P6）：

| 视图 | 宽窗口（内容宽 ≥ 1000） | 窄窗口 |
| --- | --- | --- |
| 封面 | 封面居中放大，歌曲信息和控制区在封面下方 | 同左 |
| 歌词 | 左栏：封面、歌曲信息、控制区；右栏：歌词 | 顶部一行小封面和歌名，下面是歌词，控制区在底部 |
| 队列 | 左栏同上，右栏换成队列 | 同歌词视图，歌词换成队列 |

- 用右下角的两个开关切换："歌词"和"队列"，同一时间最多开一个，两个都关就是封面视图。快捷键分别是 `L` 和 `Q`。
- 下次打开播放页时回到上次的视图。如果当前歌曲没有歌词，歌词视图显示对应的状态说明（§5.7），不自动切回封面。

## 2. 铺满窗口与自动隐藏

### 2.1 铺满窗口（P5）

- 窗口装饰为"应用绘制"时，播放页盖住顶栏，从窗口最上沿开始。窗口按钮浮在右上角，改成适合深色背景的白色样式（悬停时出现半透明白底），颜色过渡沿用 motion-choreography §2.2。顶部 48 像素的空白处可以拖动窗口、双击最大化，和顶栏一样。
- 装饰为"无"时没有窗口按钮，其余相同。装饰为"系统"时，播放页从系统标题栏下面开始，系统标题栏不受影响。
- 左上角是关闭按钮（`expand_more`）。`Esc` 关闭播放页；如果处在全屏，第一次 `Esc` 先退出全屏。
- **真正的全屏**：右上角的 `⛶` 或 `F` 键把窗口切换到全屏（`showFullScreen`），再按一次回到原来的窗口状态（最大化或普通）。全屏时没有窗口按钮。关闭播放页时，如果窗口是由播放页切成全屏的，一并退出全屏。

### 2.2 自动隐藏（P4）

播放中，鼠标停止移动、键盘也没有输入 3 秒（可改，§9）后，下面这些淡出（`slowEffects`）：

- 控制区：进度条、播放按钮、音量、右下角的开关
- 顶部的关闭、全屏、窗口按钮
- 鼠标指针（`Qt.BlankCursor`）

留下的只有背景、封面、歌名和歌手，以及歌词。被隐藏的元素位置不动，只变透明，其他内容不跟着挪。

- **重新显示**：鼠标移动或按任意键时淡入（`fastEffects`）。第一次按键只负责唤出控件，不执行动作，`Space` 除外：它照常播放或暂停。
- **不隐藏的情况**：已暂停；鼠标停在控制区上；键盘焦点在控制区里（按 `InputMode.keyboard` 判断）；有菜单、对话框或面板打开；歌词处于浏览模式（§5.4）；减少动态效果开启时照常隐藏，只是没有渐变，直接消失。
- 隐藏期间控件不接收点击，第一次点击只负责唤出控件。
- 读屏软件始终能读到全部控件，隐藏只是视觉上的。

## 3. 背景（P1、P2）

### 3.1 动态流光

我理解的"流光"是这样的：从封面取出几种颜色，形成几团很大、边缘柔和的色块，缓慢地漂移、旋转、彼此交融，像有光在背后流动。这也是 Apple Music 播放页背景的样子。如果你说的不是这个，请纠正。

做法是**网格渐变**（mesh gradient），自己写一个片段着色器（`ShaderEffect`，经 ShaderTools 编译）：

- **颜色来自封面本身**：把封面缩到 5×5，每个像素作为一个控制点的颜色。这样保留了封面颜色的空间分布：上方偏蓝的封面，背景上方也偏蓝。控制点之间做平滑插值（双三次），没有接缝。
- **流动**：每个控制点按各自的低频噪声缓慢漂移，幅度大约是网格间距的 40%；整体再以大约 90 秒一圈的速度缓慢旋转。速度可调（§9）。
- **保证文字可读**：控制点的颜色先转换到 HCT，保留色相和彩度，把色调压到 18–42 之间。这样白色文字在背景任意位置的对比度都不低于 5:1，不必额外加遮罩。阈值在原型中用浅色、高饱和的封面验证。
- **防止色带**：输出时叠加一层很淡的蓝噪声抖动。深色大面积渐变在 8 位色深下会出现明显的色阶，必须处理。
- **开销**：控制点只有 25 个，每帧只算一遍全屏片段，不需要模糊，比"多层模糊封面"便宜得多。暂停播放后流动慢慢停下（大约 2 秒）；窗口最小化、隐藏或播放页关闭时完全停止。
- **切歌**：新旧两组控制点颜色用同一个进度过渡（`slowEffects`，motion-choreography §4），位置不跳。

### 3.2 其他样式与退路

| 样式 | 用途 |
| --- | --- |
| 流光（默认） | 如上 |
| 模糊封面 | 封面放大到铺满、重度模糊、压暗（`MultiEffect`），静止不动 |
| 纯色 | 取封面主色压到色调 20，适合不喜欢动态背景或机器较弱的用户 |

- 软件渲染（没有着色器）时自动退回为由同样 5×5 颜色生成的静态渐变，用 `Gradient` 实现，不需要着色器。
- 减少动态效果时，流光静止，退化为一帧不动的网格渐变。

### 3.3 始终深色（P2，即 UQ-05）

无论外壳是亮色还是暗色，播放页都用深色背景配白色前景。理由是 Apple Music 就是这样做的；从封面取色、压暗之后的背景本来就是深色，白字最稳。前景的层级是：主文字白色；次要文字白色 60%；未唱到的歌词白色 35%。

## 4. 封面（P3）

目标是让封面像一张实物唱片封套，有厚度、会反光，而不是贴在背景上的一张图。

| 效果 | 做法 |
| --- | --- |
| 投影 | 大而柔和的投影，颜色取封面最暗的颜色并压暗，向下偏移。封面像是浮在背景上，背景被它"压"出一片阴影 |
| 暂停时缩小 | 播放时比例为 1；暂停时缩到 0.86，投影同时变小变淡，像封面落回了桌面。用 `defaultSpatial` 弹簧，会有一点点回弹，这是 Apple Music 的标志性动作 |
| 悬停倾斜 | 鼠标在封面上方时，封面朝鼠标方向倾斜，最多 6°（绕 X、Y 轴的 `Rotation` 本身带透视）。鼠标离开时用弹簧回正 |
| 高光 | 倾斜时，一块很淡的白色径向渐变反向移动，像光从表面滑过，裁在封面的圆角内 |
| 圆角 | `Theme.shape.medium`（12）。播放页不用 MD3E 的异形形状（README §2.3） |

- 投影和项目的"层级不用阴影"原则冲突（项目规定阴影只用于弹出层）。这里作为播放页语言的例外：Apple Music 的封面立体感主要来自投影，去掉之后就没有厚度了。**需要维护者确认（P3）**。
- 减少动态效果时，不倾斜，暂停时也不缩放，只保留投影。

## 5. 歌词视图

### 5.1 每一行的组成

```text
   ro   ku    ji
  [六] [時]  [の]  ……          ← 注音式音译（§6，能对齐时）
   六時の鐘が鳴る               ← 原文：逐字填充
   六点的钟声响起               ← 翻译：小一号（原文的 60%），白色 35%→60%
```

- 顺序是注音、原文、翻译。不能对齐成注音的音译另起一行，放在原文和翻译之间，字号是原文的 60%。
- 默认左对齐、粗字重，字号随右栏宽度变化（大约 30–44 像素），用户可以整体放大缩小（§9）。字体通过 `Fonts.font(weight, size)` 取，不直接设 `font.weight`（README §4.2）。
- 行与行之间留出大约原文字号 0.9 倍的空白；同一行内各部分的间距更小，让一组看起来是一个整体。

### 5.2 滚动（P7）

- **当前行的位置**：在歌词区高度 30% 的地方（偏上，P11 可改为居中）。已唱过的行留在上面，下面能看到接下来的四五行。
- **瀑布式跟进**：换行时，各行不是一起移动，而是从当前行开始逐行延迟大约 35 毫秒，各自用弹簧（`defaultSpatial`）滑到新位置。整体像水流一样依次跟上，这是 Apple Music 歌词最有特点的地方。
- **按距离淡化**：
  - 当前行不透明度 1、无模糊、比例 1。
  - 其他行不透明度 0.35，比例 0.96，以行首为缩放原点，不会左右晃动。
  - 模糊按与当前行的距离增加：每行 1.2 像素，最多 5 像素。模糊只作用于可见的行，可以整体关闭（§9）。
  - 以上各项都随换行用 `defaultEffects` 过渡。
- **布局**：不用 `ListView`。所有行用 `Repeater` 生成，每一行的纵坐标由前面各行的高度累加得到；可见区域之外的行不做模糊、不跑弹簧。一首歌通常不超过 150 行，这样做开销不大，也方便控制每一行的延迟。

### 5.3 当前行的高亮

- **逐字歌词**（`timing = Words`）：
  - 每个字从左到右"灌满"：已唱的部分白色 100%，未唱的部分 35%，两者之间是一段柔和的过渡边，宽度大约半个字。填充进度由 `PlaybackClock` 逐帧计算，不会一跳一跳。
  - 每个字唱到时向上浮起大约字号的 4%，用弹簧过渡；整行唱完后，等这一行不再是当前行时一起落回。
  - **长音**：一个字持续 1 秒以上、而且字数不多时，这个字慢慢放大到 1.08 倍，周围出现一圈柔和的白色辉光；唱完后回落。这个效果可以关闭（§9）。
- **逐行歌词**（`timing = Lines`）：整行在 `defaultEffects` 内从 35% 变亮到 100%，不做填充。
- **纯文本歌词**（`PlainText`）：不滚动、不高亮，可以自由滚动阅读，顶部提示"歌词没有时间信息"。
- **同时有多行**（`activeLines` 有多个，例如和声、重叠）：每一行各自高亮，滚动以最早开始的一行为准。
- **一行唱完但下一行还没开始**：保持高亮，直到下一行开始；间隔较长时显示间奏（§5.5）。

### 5.4 浏览模式

- 用滚轮或拖动翻看歌词时进入浏览模式：停止跟随，所有行去掉模糊，不透明度统一升到 0.6。
- 悬停的行出现一块半透明的白色圆角底；点击就跳到这一行开始的位置并退出浏览模式。拖动时不触发跳转。
- 停止操作 3 秒后自动回到跟随模式，滚回当前行（P7）。按 `Esc` 立即回到当前行，回到之后再按一次才关闭播放页。
- **键盘**：`Tab` 进入歌词区后，`↑`、`↓` 逐行移动焦点（等于进入浏览模式），`Enter` 跳到焦点所在的行。歌词区只占一个 Tab 停留点，和其他列表一致。

### 5.5 间奏

前一行结束到下一行开始之间超过 4 秒（包括歌曲开头，以及歌词里的空行）时，在下一行的位置上方显示三个圆点：

- 三个点在间奏期间依次从 35% 变亮到 100%，表示还剩多少时间，同时整体缓慢呼吸，以 1.0 和 1.06 倍为两端。
- 间奏结束前大约 0.5 秒，三个点先放大一下再收缩消失，下一行接着亮起。

### 5.6 翻译、音译的对齐

- 翻译、音译各自带时间轴。按时间与原文对齐：取与原文行时间重叠最多的那一行；没有时间轴时按行号对齐。规则用示例歌词验证后写进本节（presentation.md §5.2 留给本文的事项）。
- 如果翻译、音译的某一行找不到对应的原文行，就不显示，不另起一行。

### 5.7 没有歌词时

`Loading`、`NoLyrics`、`Instrumental`、`Failed` 分别显示一句说明，位置和当前行一致：

| 状态 | 说明 |
| --- | --- |
| `Loading` | 骨架行 |
| `NoLyrics` | "暂无歌词" |
| `Instrumental` | "纯音乐，请欣赏" |
| `Failed` | "歌词加载失败"，带"重试" |

## 6. 日语音译：注音式（P9）

### 6.1 样式

- 罗马音以小字写在对应的汉字或假名正上方，类似振假名（ruby）：字号是原文的 42%，白色 60%。高亮时跟着下面的字一起变亮。
- 每个字（或词）是一个小单元，罗马音在上、原文在下，罗马音相对原文居中。罗马音比原文宽时，这个单元按罗马音的宽度展开，原文居中。这样做最简单，但会让原文字距不均匀，第一版先这样，等算法讨论时再改进（§6.4）。
- 一首歌只要有一行用了注音，**所有行都预留注音的高度**，保证行距一致，滚动节奏不乱。

### 6.2 适用范围

- 能把罗马音对齐到每个字时，就用注音式；对不齐的行退回为原文下方单独一行（§5.1）。
- 第一版只对日语开启：歌词里出现假名就判定为日语歌，整首都用这种方式。中文拼音、粤语注音以后也可以用同样的样式，是否开启另行决定。

### 6.3 数据

- 后端的歌词有六轨：原文、翻译、音译，各分逐行和逐字两种（[queue-and-lyric-clock.md §3](../../api/queue-and-lyric-clock.md)）。
- 如果音译有逐字轨，而且每个音节都带时间，可以直接按时间把音节对应到原文的字上。这是最可靠的情况。
- 只有逐行音译时，就需要文本对齐算法：把假名转写成罗马音，再和音译文本匹配；汉字的读音由夹在中间的部分推出。

### 6.4 算法（之后再讨论）

先定好接口：

- 输入：原文的字（或词）序列和这一行的音译文本，可能带每个音节的时间。
- 输出：每个原文单元对应的罗马音片段；对不上的单元返回空。

第一版先只做"有逐字音译轨"的情况。其余情况在实现阶段与维护者讨论后再定。

## 7. 控件与键盘

播放页内的按键（这些按键不在输入框里时才生效，播放页里也没有输入框）：

## 9. 自定义（P10、P11）

### 9.1 入口

## 10. 实现步骤

1. **基础**：
   - 局部配色机制（§9.1）。
   - `App.lyrics`：展示层接口，先用假数据。
   - 示例歌词补一首原创的日语歌，带逐字音译轨、长音和长间奏（修改 `generate_samples.py` 后重新生成）。
   - 如果要做向下拖动关闭，`Spring` 需要加 `animateTo(target, velocity)`。
2. **骨架**：
   - `Cirrus.Player` 模块（`ui/player/`）和 `PlayerPage` 覆盖层。
   - 三个视图、宽窄布局、控制区、铺满窗口和全屏、自动隐藏、浮动窗口按钮。
   - 与迷你播放条之间的过渡（motion-choreography §2）。
3. **背景与封面**：流光着色器、模糊封面、纯色、软件渲染的退路，封面立体效果。
4. **歌词**：
   - 滚动、淡化、浏览模式、间奏。
   - 逐行和逐字高亮、长音效果。
   - 翻译和音译；注音式先接逐字音译轨。
5. **队列与自定义**：只读队列，显示设置面板，设置页的"播放页"分组。

每一步都在离屏截图和 Gallery 中检查，最后在真机上检查流畅度：流光、模糊、逐字高亮这三项在集成显卡上要能稳定 60 帧。

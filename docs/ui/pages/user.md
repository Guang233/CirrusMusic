# 用户页设计（已评审，2026-11-10）

**维护者已定（2026-11-10）**：
- 内容：创建和收藏的歌单、听歌排行、关注和粉丝列表、关注和取消关注。
- 入口：评论的头像和昵称、歌单的创建者、歌手页上的"用户主页"。不加"我的主页"入口（U3）；自己的主页从自己的评论等处照样能进。
- 不标用户类型（没有"用户／音乐人"那一行）；U1、U2、U4 按建议。
- 网易云的"动态"不做（范围决定，见 [14-roadmap §6](../../14-roadmap-and-backlog.md)）。

用户页就是网易云里点一个人打开的个人主页。音乐人在网易云有两个页面：用户页（账号）和歌手页（艺人资料），ID 不同；两边互相能跳过去。版式和歌手页同一个家族（[artist.md](artist.md)）：圆形头像的头部随内容滚走，操作行，标签页，滚走后顶部出现紧凑条、标签栏固定在它下面。

## 1. 后端

后端现在只有**当前账号自己**的读取（自己的歌单 `MyPlaylists`、听歌排行 `ListeningRanking`），没有任何"看别人"的接口，全部要新加。接口按参考项目（api-enhanced，MIT）的路径，字段要先实测（§7 第 1 步）：

| 内容 | 接口 | 说明 |
| --- | --- | --- |
| 头像、昵称、签名、等级、关注数、粉丝数、歌单数、是否已关注 | `/api/v1/user/detail/{uid}`（Weapi） | 参考文档写"登录后调用"，游客能不能读要实测 |
| 创建的歌单、收藏的歌单 | `/api/user/playlist`，`uid` 换成对方 | 和 `MyPlaylists` 同一个接口；那边绑定当前账号，这里放开任意 uid（只读） |
| 关注列表 | `/api/user/getfollows/{uid}`，偏移分页 | |
| 粉丝列表 | `/api/user/getfolloweds/{uid}`，按时间游标分页 | 粉丝可能几十万，只能一页页往下翻 |
| 听歌排行（最近一周、所有时间） | `/api/v1/play/record`，`uid`＋`type` | 和 `ListeningRanking` 同一个接口；对方不公开时服务端拒绝（错误码待实测），按"不公开"显示 |
| 关注、取消关注 | `/api/user/follow/{uid}`、`/api/user/delfollow/{uid}`（Weapi） | 写操作，要登录；走和收藏一样的分派器（`CollectionWrites` 的规则：一次一条、换号不发、Unknown 提示"可能没有成功"）。可能碰到风控（像评论那样），实测再看 |
| 用户 ↔ 歌手 | 用户详情里的歌手 ID；歌手详情里的用户 ID | **字段名待实测**（印象中是 `profile.artistId` 和歌手头部信息里的 `user`），没有就不显示跳转 |

后端改动按 [HANDOFF](../../HANDOFF.md) 的约定：新的 `ApiOperation`、严格映射（多出的行截断、缺的可选字段为空，不整页拒绝）、`music.invalid_why` 原因日志、读操作打开断连重发。

## 2. 版式

```
╭────────╮
│  头像  │   昵称                Lv.8                ← headlineLarge；等级是小号标签
│  圆形  │   一行签名……                     更多     ← 超出时对话框（阅读对话框，可选择）
│  200   │   关注 120 · 粉丝 3.4万 · 歌单 25          ← 数字可点：切到对应标签
╰────────╯
[＋ 关注]  [歌手主页]                                ← 自己的主页没有关注按钮
 歌单   听歌排行   关注 120   粉丝 3.4万               ← 标签
──────────────────────────────────────────
 （标签内容）
```

- **头部**：圆形头像（宽 200／窄 140，没有时占位 `person`）。和歌手页的区别：没有类型行，有等级标签，数量行是关注／粉丝／歌单。签名一行，超出时"更多"打开阅读对话框（签名不长，不单独设标签）。
- **操作行**：
  - 关注／已关注（Tonal，`person_add`／`how_to_reg`）。未登录点击打开登录；自己的主页不显示。
  - 音乐人多一个"歌手主页"（Text 按钮，`mic`），进对应的歌手页。
- **标签**：歌单、听歌排行、关注（带数）、粉丝（带数）。键盘与歌手页相同：标签栏一个 Tab 停留点，←／→ 切换，Ctrl+PageUp／PageDown。
- **滚动**：与歌手页相同，紧凑条是小圆头像、昵称、关注按钮。

## 3. 各标签

### 3.1 歌单

- 两段："创建的歌单 N"、"收藏的歌单 N"，各是一组歌单卡片（`CollectionGrid`，与音乐库相同：封面、标题、"N 首"）。点卡片进歌单页。
- 接口一次给全部歌单（和音乐库的歌单标签一样读完整列表，§1）。
- 没有歌单时这一段不显示；两段都没有："TA 还没有歌单"（自己的主页："还没有歌单"）。

### 3.2 听歌排行

- 上方"最近一周／所有时间"两段切换（与音乐库的听歌排行相同），下面是歌曲表格加播放次数比例条（复用 `RankingPage` 的列表）。
- 对方不公开：空状态"TA 没有公开听歌排行"，图标 `lock`。自己的主页读自己的（和音乐库的排行同一份数据）。

### 3.3 关注、粉丝

- 用户列表：圆形头像、昵称、签名（一行，次要文字）、右侧关注按钮（已登录且不是自己时）。点行进那个人的用户页。
- 滚到底分页加载（`LoadMoreFooter`）。
- 列表里的关注按钮和头部的是同一个写操作。

## 4. 入口

| 入口 | 做法 |
| --- | --- |
| 评论 | 头像和昵称可点（手形光标），回复里的也一样；键盘：评论行菜单加"查看用户主页" |
| 歌单页 | 头部的创建者名字可点（需要歌单详情带出创建者的 uid；现在映射只有名字，要补） |
| 歌手页 | 音乐人在操作行多一个"用户主页"（Text 按钮），进 TA 的用户页 |

## 5. 状态

- 加载：头部骨架（圆形＋几行），标签内容各自的骨架。
- 用户不存在或已注销：整页错误状态"找不到这个用户"。
- 失败：整页或标签内的失败状态加重试（`TabState`）。
- 关注失败：提示条（"关注没有成功"／"可能没有成功"），按钮回到原状态；风控拒绝时说"网易云拒绝了这次操作"。

## 6. 不做的

动态、编辑资料、私信、用户创建的播客、访客记录、黑名单、徽章与会员图标（只显示等级）。

## 7. 实现步骤

1. **实测字段**（游客身份，几次只读请求，临时钩子，不提交）：用户详情（普通用户和一个音乐人各一）、用户歌单、关注、粉丝、听歌排行（一个公开、一个不公开）、歌手详情里的用户字段。确认游客能读哪些、字段名和分页方式，回写 §1。
2. **后端读取**：五个读操作和映射、测试、文档（`docs/api/` 新开一页）。
3. **用户页**：页面、模型（`UserPageModel`：头部、四个标签各自的模型）、Gallery 不需要（页面用假数据源也能打开）。
4. **关注写操作**：后端写操作＋分派器，按钮和列表里的关注；维护者登录实测。
5. **入口**：评论、歌单创建者、歌手页。

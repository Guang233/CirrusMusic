# 首页设计

状态：**待维护者评审**（2026-10-31）。评审通过前不写 QML；现有 `ui/app/FeedPage.qml` 只是原型，按本文重写。

## 1. 首页做什么

用户打开应用，第一件事通常是"放点什么"。首页只做这一件事：**一次点击开始听，而且听的是为这个人、为今天准备的内容。**

所以首页和发现页分开：

| | 首页 | 发现 |
| --- | --- | --- |
| 问题 | 我现在听什么？ | 还有什么可听？ |
| 内容 | 今日推荐、私人 FM、最近听过、相似歌曲、推荐歌单 | 榜单、歌单分类与精品歌单、新碟、歌手 |
| 依据 | 账号（未登录时退化） | 公共目录 |

首页不放轮播横幅（后端没有横幅接口，也不想要广告位）、不放问候语（"早上好，xx"不帮用户做任何事）、不做无限滚动。页面一屏半到两屏，能看到底。

## 2. 可用数据

只用后端已有的读取（`docs/api/`），不编造字段：

| 区块 | 后端读取 | 需要登录 | 备注 |
| --- | --- | --- | --- |
| 今日推荐 | `DailyRecommendations`（[discovery-and-fm.md](../../api/discovery-and-fm.md)） | 是 | 每首歌带推荐理由（按歌曲 ID 对应，可能没有）；读取不强制服务端换一批 |
| 私人 FM | `PersonalFm` + 已有的 FM 连续播放 | 是 | 首页不预取，点播放才开始 |
| 最近听过 | `recentSongs`（[cloud-history-reads.md](../../api/cloud-history-reads.md)） | 是 | 网易云的云端记录 |
| 和《X》相似的歌 | `SimilarSongs`（[discovery-browse-reads.md](../../api/discovery-browse-reads.md)），种子是"最近听过"的第一首 | 否（种子要登录才有） | 服务端分页未验证，只取第一批的前几首 |
| 推荐歌单 | 登录：`DailyRecommendedPlaylists`；未登录：`RecommendedPlaylists`（personalized） | 前者是 | 两者是不同接口，标题也不同 |
| 新碟 | `LatestAlbums` | 否 | 只在未登录时放在首页，见 §4.3 |

## 3. 视觉方向

整体是 MD3 Expressive 的外壳语言，颜色只用动态配色角色。克制地处理大部分区块，把力气花在一个地方：**顶部的"今日"**。

### 3.1 标志元素：日期数字

网易云的每日推荐一直用日历上的日期做图标，用户认得它。首页顶部把这个日期放大成一块版面：

```text
 31            十月 · 星期六
               今日推荐 · 30 首
```

- 日期数字用 MiSans，112 px，字重 200（ExtraLight），`onPrimaryContainer`。细而大的数字和旁边 `titleMedium` 的小字形成反差，是整页唯一的"大字"。
- **字重表示状态。** 当前播放的歌曲属于今日推荐时，数字的字重弹到 630（Bold）；离开今日推荐（换歌单、停止、切到 FM）时回到 200。用 `slowEffects` 弹簧驱动，过渡中可以打断。这用到了 MiSans 无级字重轴（[README §4.2](../README.md)），别的字体做不到。用户不用读任何文字，扫一眼就知道"今天的歌正在放"。
- 减少动态效果时字重直接切换。用户改成系统字体或自定义字体后，`Fonts.font()` 照常设置字重：字体有对应字重就变，没有就不变，不影响功能。

这是本页唯一的冒险。其余区块都不加装饰性动效，也不用异形形状，只保留 MD3 的状态层和弹簧。

### 3.2 颜色

不定义固定色值，全部取当前配色方案的角色。外壳选择"跟随封面"时首页会随正在播放的歌换色，这是期望的效果。

| 位置 | 容器 | 内容 |
| --- | --- | --- |
| 页面底色 | `surface` | `onSurface`、`onSurfaceVariant` |
| "今日"卡片 | `primaryContainer` | `onPrimaryContainer` |
| 私人 FM 卡片 | `tertiaryContainer` | `onTertiaryContainer` |
| 歌单／专辑卡片、分段歌曲列表 | `surfaceContainer` | `onSurface` |
| 推荐理由 | 无容器 | `onPrimaryContainer`，不透明度 0.8 |

"今日"用 primary、FM 用 tertiary：两个入口并排时一眼分得开，而且都跟着种子色走。

### 3.3 字体层级

全部是 MiSans，通过 `Theme.type.*` 取；只有日期数字用 `Fonts.font(weight, 112)`。

| 用途 | 样式 |
| --- | --- |
| 日期数字 | 112 px，字重 200 ↔ 630 |
| 月份与星期、"今日推荐 · 30 首" | `titleMedium` |
| 推荐理由 | `bodyMedium` |
| 区块标题 | `titleLarge` |
| "查看全部" | `labelLarge` |
| 卡片标题／副标题、歌曲行 | 沿用 `CollectionCard`、`SongList` |

### 3.4 形状

- "今日"和 FM 卡片：`Theme.shape.extraLarge`。
- 今日卡片里的封面：前 4 首歌的封面叠成一摞，每张 `Theme.shape.large`，依次错开 24 px、向右下轻微旋转（0°、4°、8°、12°）。不做形状遮罩（理由见 §8 D2）。
- 主播放按钮：沿用迷你播放条的规则，`Filled`、`Large`，播放中变为方形（Square）。

## 4. 布局

内容区宽度按 MD3 窗口分级（[README §6.2](../README.md)）。下面的宽度是**内容区**宽度（扣掉导航栏）。内容最大宽度 1200 px，更宽时居中，两侧留白（D4）。

### 4.2 中等（600–839）

- FM 卡片移到今日卡片下方，变成一条高 72 px 的横条：图标、"私人 FM"、播放按钮。
- 今日卡片高 216，封面堆缩小到 120 px，推荐理由只显示一行。
- 歌曲区块变单列 6 行；歌单行列数自动减少。

### 4.3 窄（< 600）

- 日期数字 72 px，封面堆隐藏。
- 只保证能播放和导航：今日卡片、FM 横条、各区块单列。

### 4.4 未登录

- 今日卡片保留日期数字（不会变粗，因为没有今日推荐），变成登录入口；FM 卡片不单独出现，并入这句话。
- "最近听过""相似的歌"整块不显示（没有种子）。"新碟上架"补位，免得页面只剩一行。
- 登录过期与未登录相同，文字改为"登录已过期，重新扫码登录后恢复今日推荐和私人 FM。"

## 5. 交互

| 对象 | 操作 | 结果 |
| --- | --- | --- |
| 今日卡片 | 点击卡片空白处、"全部 30 首" | 打开每日推荐页 |
| 今日卡片 | 播放按钮 | 从第一首开始播放今日推荐；正在播放今日推荐时变为暂停 |
| FM 卡片 | 播放按钮 | `App.player.startFm()`；FM 播放中变为暂停 |
| FM 卡片 | FM 播放中 | 卡片显示当前歌曲的封面、歌名、歌手，加一个"下一首"按钮；等待下一首时按钮里显示加载指示器（`fmWaiting`） |
| 歌曲行 | 单击／Enter | 以该区块的 6 首为队列从这首开始播放（与 `SongList` 现有行为一致） |
| 歌曲行 | 更多菜单 | 沿用 `SongList`：查看专辑、查看歌手 |
| 卡片 | 单击 | 打开歌单／专辑详情 |
| 区块标题 | "查看全部" | 最近听过 → 音乐库的最近播放；推荐歌单 → 发现页的歌单；新碟 → 发现页的新碟 |
| 页面 | 刷新按钮、F5 | 重新读取所有区块；按钮文字是"刷新"，不叫"换一批"（服务端不保证换内容） |

键盘焦点顺序：刷新 → 今日卡片 → 今日播放 → FM 播放 → 各区块（标题的"查看全部"在区块内容之前）。

## 6. 状态

首页由几个互相独立的读取组成，**按区块分别加载、分别失败**，不让一个接口拖垮整页。

| 状态 | 表现 |
| --- | --- |
| 首次加载 | 各区块各自显示骨架：今日卡片是同色容器里的两条文字块和一个圆形按钮；歌曲区块用 `ListSkeleton`；歌单行是方块。150 ms 内到达的区块不显示骨架（沿用 `PageState.skeletonDelay`） |
| 区块到达 | 该区块淡入并上移 16 px（`standardDefaultSpatial`），骨架同时淡出。只在首次加载时；返回首页时恢复滚动位置，不再播放 |
| 刷新 | 内容保留，顶部显示细进度条；某区块刷新失败时保留旧内容，区块标题旁出现"刷新失败 · 重试" |
| 单个区块失败 | 区块位置显示一行：图标 + "推荐歌单没有加载出来" + "重试"按钮。不弹整页错误 |
| 全部失败（通常是离线） | 整页 `StateMessage`："连不上网易云音乐。检查网络后重试。" + "重试" |
| 今日推荐为空 | 今日卡片保留日期，文字改为"今天的推荐还没生成，稍后刷新试试。"，播放按钮隐藏 |
| 第一首没有推荐理由 | 第二行改为歌手名。理由文字按服务端原样显示，不改写（§4.1 图中的歌名和理由只是示例） |
| 相似歌曲为空 | 整块隐藏，不显示空状态（这是锦上添花的区块） |
| 最近听过为空 | 整块隐藏，相似歌曲也随之隐藏 |
| 未登录、登录过期 | 见 §4.4 |
| 跨过零点 | 页面重新显示时若本地日期已变，自动刷新一次。后端没有跨日时钟，以本地日期为准 |

## 7. 动效

- **首次加载**：区块按到达顺序依次出现，见 §6。不做整页统一编排，避免为等最慢的接口而推迟显示。
- **日期字重**：见 §3.1，`slowEffects`。
- **封面堆**：鼠标悬停在今日卡片上时，四张封面的错开距离从 24 px 弹到 32 px、旋转角各加 2°（`defaultSpatial`），移开回弹。这是封面堆唯一的动效。
- **播放按钮**：圆形↔方形，沿用迷你播放条的弹簧。
- **减少动态效果**：全部直接切换，区块不位移只淡入。

## 9. 实现所需的展示层改动

评审通过后再做，记在这里方便评估工作量：

- `HomePageModel` 拆成按区块独立的状态：每个区块有自己的 `loadState`、`error`、`retry()`。页面级 `refresh()` 刷新全部。
- 今日推荐需要：歌曲总数、前 4 首的 `coverKey`、第一首的标题与推荐理由、全部 key（供播放）、"当前歌曲是否在今日推荐里"。`SongInfo` 增加可选的 `reason`。

- 推荐歌单按登录状态选用 `DailyRecommendedPlaylists` 或 `RecommendedPlaylists`；新碟用 `LatestAlbums`。
- 假数据源补齐上述读取，并能分别让各区块失败或为空（`FakeControls` 增加对应开关），在 Gallery／调试开关中检查 §6 的每个状态。
- `Feed.Discover` 不再与首页共用模型，发现页另行设计。

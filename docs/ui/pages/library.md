# 音乐库设计（已评审，2026-11-02）

**维护者已定**：L1、L3、L5 按建议；**L2 改为："我喜欢的音乐"就是一个歌单**，与其他歌单没有区别（打开的就是歌单页）；L4 随之取消（歌单页怎样，它就怎样）。全部按 MD3E 规范做。

音乐库是"我的东西"的总入口：喜欢的歌、歌单、收藏的专辑、关注的歌手、订阅的播客，以及听过什么。现在的原型是一页五个标签（喜欢、歌单、专辑、歌手、最近），把两种不同的东西混在了一起：**歌曲清单**（喜欢、最近、排行，要表格、播放、查找）和**收藏的集合**（歌单、专辑、歌手、播客，要卡片网格）。本设计把它们分开。

## 1. 后端能给什么

| 内容 | 接口 | 说明 |
| --- | --- | --- |
| 我的歌单 | 用户歌单，分页 | 创建的和收藏的混在一起，每条带是否收藏、创建者；不能假定第一条就是"我喜欢的音乐" |
| 喜欢的歌 | 喜欢的歌曲 ID | 一次返回全部 ID（最多 10 万），没有详情，要按需补；顺序是服务给的顺序，文档不保证是喜欢的时间 |
| 收藏的专辑、关注的歌手、订阅的播客 | 各自分页，带总数（可能缺） | |
| 最近播放 | 歌曲（最多 100）、歌单、专辑、播客、声音 | 网易云的云端记录（维护者定过：历史展示以云端为准） |
| 听歌排行 | 最近一周／所有时间 | 云端 |
| 云盘 | 列表、详情、已用／总空间 | **不能播放**：云盘歌曲没有可用的音源绑定（[account-library-reads.md](../../api/account-library-reads.md) §3） |
| 写操作 | 喜欢、收藏、关注、订阅，新建／改名／删除歌单 | 已有接口（collection-writes、playlist-management-writes） |

全部需要登录。

## 2. 音乐库页

```
音乐库
╭──────────────────────╮ ╭──────────────╮ ╭──────────────╮
│ ♥                    │ │ ◷  最近播放   │ │ ▁▃▅ 听歌排行  │      ← 歌曲清单：三张卡片，各开一页
│ 我喜欢的音乐          │ │ 100 首        │ │ 本周：落日航线 │
│ 248 首         [▶]   │ ╰──────────────╯ ╰──────────────╯
╰──────────────────────╯
 歌单 12   专辑 4   歌手 3   播客 1                              ← 收藏的集合：标签，固定在顶部
 (全部) (创建的) (收藏的)                         [＋ 新建歌单]   ← 只在"歌单"标签
┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐
│    │ │    │ │    │ │    │ │    │ │    │                      ← 卡片网格，滚到底分页
└────┘ └────┘ └────┘ └────┘ └────┘ └────┘
```

- **标题**"音乐库"（headlineMedium，与搜索页的标题同级）。
- **歌曲清单卡片**一行三张，与首页的卡片同一家族（extraLarge 圆角、色调分层，不用阴影）：
  - **我喜欢的音乐**：最宽，primaryContainer 底，实心红心图标，"248 首"，右下角播放按钮（Filled 图标按钮，播放全部喜欢的歌）。它是账号的"我喜欢的音乐"歌单的快捷入口，点开就是那个歌单的歌单页；这个歌单也照常出现在"创建的"歌单里。
  - **最近播放**：surfaceContainer 底，"100 首"（云端记录的条数）。
  - **听歌排行**：surfaceContainer 底，副标题是本周第一的歌名（没有时写"看看这周常听什么"）。
  - 点卡片打开对应的页（§3）。窄窗口（< 840）时三张换成一列三条 72 px 高的横条，与首页的 FM 横条同样处理。
- **标签**：歌单、专辑、歌手、播客，带数量（有的话；0 不写数字，与搜索页一致）。滚动后固定在顶部（与歌手页、搜索页同一机制）；Ctrl+PageUp／PageDown 切换；记住上次所在的标签。
- **歌单标签**：
  - 筛选纸片（MD3 筛选纸片，单选）：全部、创建的、收藏的。按后端的"是否收藏／创建者"分；分不出来的放在"全部"里。
  - 右侧"新建歌单"（Tonal 按钮）：打开对话框（标题、"新建"／"取消"），建好后打开新歌单的页面。外壳的对话框规则已经预留了它（shell.md §4）。
  - 卡片：封面、标题、"N 首"；收藏的歌单副标题写创建者。
- **专辑、歌手、播客标签**：卡片网格（`CollectionGrid`，与歌手页的专辑、搜索结果相同），歌手为圆形，播客副标题"N 期"。
- 每个标签第一次显示时才请求，各自分页（每页 30）、各有加载／失败／空状态（"还没有收藏的专辑"，附一句去哪儿收藏）。
- **未登录**：整页一个登录提示（"登录后，喜欢的歌、收藏的歌单都在这里"＋"扫码登录"），不显示卡片和标签。

## 3. 歌曲清单页

"我喜欢的音乐"就是歌单页（L2），不另做。另外两个用歌单页的版式（`SongCollectionPage`：头部、操作行、表格、紧凑条），封面位置是图标块（与每日推荐的日期块同一种做法：200×200、extraLarge 圆角、色调底色），各自不同的地方：

### 3.1 我喜欢的音乐

- 打开账号的"我喜欢的音乐"歌单（歌单页，[playlist.md](playlist.md)）：排序、查找、从歌单移除都与其他自建歌单相同。
- 后端要能认出这个歌单：网易云的用户歌单里它有特殊类型，现在的后端摘要没有这个字段（[personal-library.md](../../api/personal-library.md) §3 写明"不假定首条就是'我喜欢'"），接真实后端时需要后端补上。

### 3.2 最近播放

- 头部：时钟图块，标题"最近播放"，说明"网易云记录的最近播放"。
- 标签：歌曲、歌单、专辑、播客、声音。歌曲是表格（最多 100 首，不分页）；歌单、专辑、播客是卡片网格；声音是声音表格（与搜索页的声音标签相同，播放等后端）。
- 没有查找和排序（顺序就是时间）。

### 3.3 听歌排行

- 头部：排行图块，标题"听歌排行"。
- 操作行：播放全部、"最近一周／所有时间"切换（ConnectedButtonGroup，与操作行同高）。
- 表格：序号就是名次，前三名用 primary 色。后端若给出播放次数或比例，在时长前加一列"播放次数"；没有就不加。

## 4. 侧边栏与首页的入口

- 侧边栏"我的"下的"我喜欢的音乐"打开那个歌单，"最近播放"打开 §3.2 的页面（现在都是打开音乐库的标签）。
- 首页"最近听过"的"查看全部"打开最近播放页。

## 5. 不做的（这一轮）

- **云盘**：能列出来但不能播放，做成页面只会是一张放不了的表。等后端有了云盘音源再做（L3）。
- 歌单、专辑等的排序和页面内查找：后端只给服务顺序且分页；歌单多的用户可以用侧边栏或全局搜索。以后需要时再加"加载全部后本地排序"。
- 本机的播放记录（SQLite 长期历史）：维护者定过以云端为准；本机记录以后可作为"最近播放"的补充。
- 视频、MV、专栏收藏：没有接口，也不在音乐功能的范围里。

- 展示层：`LibrarySource` 按后端拆成 `myPlaylists(page)`、`likedSongKeys()`（已有）、`likedPlaylist()`（"我喜欢的音乐"歌单）、`savedAlbums(page)`、`followedArtists(page)`、`subscribedPodcasts(page)`、`recentSongs/Playlists/Albums/Podcasts/Voices`、`listeningRanking(period)`、`createPlaylist(title)`；音乐库页的每个标签一个分页模型；喜欢页、最近播放页、排行页各一个页面模型。侧边栏的歌单改为只读 `myPlaylists`（shell.md §6 的待办）。
- 组件：`SongCollectionPage` 的封面位置支持图标块（`DateTile` 那样的组件）。
- 假数据：已有的喜欢、歌单、专辑、歌手；加订阅的播客、云端最近播放各类、两种排行。

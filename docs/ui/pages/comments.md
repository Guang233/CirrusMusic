# 评论页设计（待评审，2026-11-03）

歌曲、歌单、专辑的评论：读、点赞、发表、回复、删除自己的。现在歌单页和专辑页的"评论 N"按钮只弹提示"评论页还在设计中"（[playlist.md §2](playlist.md)），本设计接上它，并给歌曲加入口。

## 1. 后端能给什么

| 内容 | 接口 | 说明 |
| --- | --- | --- |
| 评论列表 | 新版排序列表：推荐／最热／最新三种排序，分页（推荐、最热按游标偏移，最新按上一页最后一条的时间），带总数（可能缺） | [comment-reads.md](../../api/comment-reads.md)；歌曲、歌单、专辑、传统节目 |
| 精彩评论 | 旧接口的第一页附带热门评论；也有单独的热门列表 | 与"最热"排序重复 |
| 楼层（回复） | 某条评论下的回复，分页（按时间） | 列表里的评论带回复数和最多 10 条预览（可能缺） |
| 每条评论 | 作者（昵称、头像、用户 ID）、正文（纯文本，可能缺＝已删除）、时间、点赞数、我是否赞过；被回复的那条的摘录（"回复 @某人：…"） | 正文是不可信文本：只按纯文本显示，不渲染链接或富文本 |
| 评论数 | 统计接口（一次最多 100 个资源） | 歌单、专辑的详情里已有评论数 |
| 写 | 点赞／取消、发表、回复、删除 | [comment-writes.md](../../api/comment-writes.md)；要登录。发表成功**不返回新评论的 ID**，也不保证马上可见（审核） |
| 没有的 | 艺人、声音（播客节目）的评论；举报；表情图片、配图；评论通知、我的评论历史 | 不做 |

读取游客也能用；写要登录。删除权限由服务器判断，界面只在"作者是我"时给删除入口。

## 2. 版式

评论是外壳里的一页（从歌单／专辑页的"评论"按钮、歌曲的行菜单进入，后退回去），不是歌单页里的标签，也不是侧边面板（C1）。

```
┌────┐ 歌单评论                                                       ← 资源头部：小封面 56、类型、标题
│封面│ 深夜通勤                                                          （点标题回到资源页）
└────┘ 共 1,286 条
┌──────────────────────────────────────────────────────────────┐
│ ( 头像 )  写下你的评论…                                         │    ← 发表框（未登录时点击打开登录）
└──────────────────────────────────────────────────────────────┘
[推荐|最热|最新]                                                       ← 排序（三段按钮组）
──────────────────────────────────────────────────────────────
( ) 雾港乐队的歌迷  · 3 天前
    这首歌陪我走过了很多个下班的夜晚。
    ┌ 回复 @Kiiro：同一个时间听同一首歌 ┐                               ← 被回复的摘录（surfaceContainer 小块）
    👍 1.2万   💬 回复   ⋮
    展开 24 条回复 ⌄                                                 ← 楼层入口
( ) …
```

- 内容宽度与其他页面相同（最多 1200，居中），评论正文一行最多约 72 个汉字宽（720 px），更宽也不拉满：长文本读起来舒服。
- 滚动后头部收起，顶部固定一条紧凑栏：资源标题＋排序按钮组＋"写评论"（Tonal 按钮，滚回顶部并聚焦发表框）。与歌单页的紧凑栏同一做法。
- 歌曲的资源头部：封面、"歌曲评论"、歌名、歌手；右侧多一个播放按钮（IconButton Tonal）。

## 3. 各部分

### 3.1 排序

- 三段按钮组（ConnectedButtonGroup，XSmall）：推荐（默认）、最热、最新。切换时列表原地替换（保留旧内容直到新的到达），回到顶部。
- 不单独放"精彩评论"区块（C2）："最热"就是它；推荐排序本身也把热评放在前面。

### 3.2 一条评论

- MD3 列表项的排法，不用卡片：头像 40（圆，`CoverArt` 的人像占位），右侧依次是
  - 昵称（titleSmall）· 时间（bodySmall，onSurfaceVariant；1 小时内"N 分钟前"，今天"HH:mm"，昨天"昨天 HH:mm"，今年"M月D日"，更早"YYYY年M月D日"）；
  - 正文（bodyLarge，自动换行，**可以用鼠标选中复制**，不识别链接）；超过 8 行折叠，末尾"展开"（Text 按钮）；
  - 被回复的摘录：surfaceContainer 底、圆角 small 的小块，"回复 @昵称："（labelLarge）加摘录（bodyMedium，最多 2 行）；摘录缺失（原评论已删）时写"原评论已删除"；
  - 操作行：赞（IconButton Standard，`thumb_up`，赞过时填充、primary 色，旁边是数量）、回复（Text 按钮）、更多（`more_vert` 菜单：复制正文、回复、删除——只在作者是我时）。
- 正文缺失（已删除、审核中）：整条显示为一行 onSurfaceVariant 的"这条评论已删除"，没有操作行。
- 评论之间不画分隔线，靠 16 px 间距和头像列对齐；悬停时整条有状态层（圆角 large，像音乐库的列表项）。

### 3.3 回复（楼层）

- 有回复的评论下面一行"展开 N 条回复"（Text 按钮，带 `expand_more`）。点开在原地展开（C3）：回复缩进到正文列，样式同评论但头像 32；每次加载 20 条，末尾"更多回复"；"收起回复"收起。
- 后端给了回复预览时，展开先显示预览，再按需请求，避免点开的一瞬间空白。
- 不做嵌套的嵌套：楼层里的回复再被回复时，用"回复 @昵称"的摘录表示，与网易云相同。

### 3.4 发表与回复

- **发表框**在排序上方（C5）：头像＋单行的"写下你的评论…"，聚焦后展开为多行输入框（最多 6 行后滚动）和"发表"（Filled，空白时不可用）。服务器的字数上限没有证据，界面不猜；只在接近后端的本地上限（4096 个 UTF-16 单元）时在右下角显示剩余字数，超过时不能发表并说明。Ctrl+Enter 发表，Esc 收起（有内容时先问是否放弃）。
- **回复**：点评论的"回复"在这条评论下面原地出现同样的输入框，带"回复 @昵称"的占位文字；一次只开一个回复框。
- 未登录：点发表框、回复、赞都打开登录对话框，不先出输入框。
- **发表成功后**（C4）：提示条"已发表"；在列表最上面插入一条本地的"我的评论"（我的头像、昵称、"刚刚"、正文），带说明"刚发表，刷新后可以点赞和回复"——后端不返回新评论的 ID，这条在本页存在期间不能赞、回复或删除；切到"最新"或刷新后由服务器的数据代替。发表失败：输入框保留内容，提示条说明原因。
- 回复成功：同样在该评论的楼层顶部插入本地回复并展开楼层。

### 3.5 点赞与删除

- 赞：先改界面（填充图标、数量 ±1），失败时撤回并用提示条说明，与歌单收藏同样处理。
- 删除：确认对话框"删除这条评论？"；成功后这条从列表淡出，资源头部的数量 −1。结果未知（超时等）时提示"可能没有删除成功，刷新看看"，不从列表移除。

## 4. 入口

- 歌单页、专辑页：操作行的"评论 N"打开评论页。
- 歌曲：歌曲表格的行菜单加"查看评论"（只有一首选中时）；以后播放页也有入口（阶段 4；按 README 播放页一节，跳转前先退出播放页）。
- 每日推荐、搜索结果等所有用 `SongTable` 的地方自动有行菜单入口。声音（播客节目）没有（后端没有绑定）。

## 5. 状态与键盘

- 加载：资源头部的骨架＋三条评论的骨架（头像圆、两行字）。失败、空（"还没有评论，来写第一条吧"，发表框仍在）、离线照常。翻页同其他列表（`LoadMoreFooter`）。
- 键盘（C7）：评论列表是一个 Tab 停留点，↑／↓ 在评论之间移动（当前评论有焦点环），Enter 展开／收起回复，L 赞，R 回复，菜单键／Shift+F10 打开"更多"菜单；Tab 从列表到下一个停留点。发表框、排序按钮组各是一个停留点。Ctrl+Enter 发表，Esc 收起输入框。
- 读屏：每条评论读作"昵称，时间，正文，N 个赞，M 条回复"。

## 6. 不做的

- 表情面板、配图、@ 提醒补全：后端没有对应能力或不在范围内。正文里网易云的表情代码（如 `[大哭]`）原样显示为文字。
- 举报、分享评论、评论通知、我的评论历史：没有接口。
- 艺人、声音的评论：后端没有绑定。播客（容器）只有部分读取接口，先不做。
- 评论区的"楼主""作者"标记：后端不保证作者身份，不推断。

## 7. 需要决定

| 编号 | 问题 | 建议 |
| --- | --- | --- |
| C1 | 评论放在哪：外壳里单独一页（后退返回），还是资源页里的标签，或从右侧滑出的面板？ | 单独一页。歌曲没有自己的页面，只有单独一页能统一歌曲、歌单、专辑三种入口；评论是长文本，需要整页宽度和自己的滚动 |
| C2 | 要不要网易云那样的"精彩评论"区块＋"最新评论"两段？ | 不要，用推荐／最热／最新三种排序。区块和"最热"内容重复，两段各自分页在桌面上也难操作 |
| C3 | 回复（楼层）怎么看：原地展开，还是打开一个对话框／侧边面板？ | 原地展开。上下文（被回复的那条）一直在眼前，不多一层窗口 |
| C4 | 发表成功但后端不给新评论 ID、也可能在审核：怎么显示？ | 在列表顶部插入本地的"我的评论"，注明刷新后才能互动；不假装它是服务器上的正式评论 |
| C5 | 发表框放哪：顶部（排序上方），还是固定在窗口底部（聊天软件那样）？ | 顶部，紧凑栏里有"写评论"按钮跳回去。底部常驻输入框占阅读空间，而评论页主要是读 |
| C6 | 要不要做播客（容器）评论？ | 先不做。后端只有排序／热门读取、没有发表，做出来是半套 |
| C7 | 键盘：列表一个停留点＋↑／↓、单键 L／R，还是每个按钮都是 Tab 停留点？ | 一个停留点＋单键。一页几十条评论，每条三个按钮，逐个 Tab 不可用；单键只在列表有焦点时生效，不和输入冲突 |

## 8. 实现时的改动（评审后）

- 展示层：新的 `CommentSource`（读：`comments(target, sort, cursor)`、`replies(target, parent, time)`；写：`setCommentLiked`、`publishComment`、`replyComment`、`deleteComment`），目标是歌曲／歌单／专辑三种 key 加类型。`Account` 加当前账号的 `userId`（判断"作者是我"）。模型：`CommentsPageModel`（资源头部、排序、分页的评论列表、本地插入的"我的评论"）、`CommentListModel`（角色：作者、头像、时间文字、正文、被回复摘录、赞数、赞过、回复数、回复预览、是否我的、是否本地）、楼层用同一个列表模型按评论展开。假数据：按资源 key 固定生成几百条评论，部分有楼层、被回复摘录、已删除的，账号自己的几条可以删除。
- 控件：评论项是页面里的组件（`CommentItem`），不进 `Cirrus.Controls`；赞按钮用 `IconButton`＋数量文字。时间文字放 `App.format.relativeTime()`。
- 外壳：`shell.openComments(kind, key)`；歌单页、专辑页的评论按钮接上；`SongTable` 行菜单加"查看评论"（信号 `commentsRequested(key)`）。
- 图标：`thumb_up`、`expand_more`／`expand_less`（若还没有）加入 `symbols.txt` 后重新生成。

# 11 · 安全、隐私与合规

> 状态：提案。前提是维护者已明确的官方 API 直连方案；本章规定实现与发布质量，不把客户端改造成可配置第三方 API 平台。

## 1. 资产与威胁边界

保护对象：账号会话、私有歌单／云盘／历史、本地音乐文件、下载内容、应用更新渠道、用户设备资源和可信 UI。

| 威胁 | 入口 | 控制 | 验收 |
| --- | --- | --- | --- |
| 凭据泄露 | 日志、崩溃报告、配置、跨域请求 | 密钥环、结构化脱敏、域绑定、诊断包预览 | TC-SECURITY |
| 跨账号数据泄漏 | 晚到请求、共享缓存、路由历史 | sessionEpoch、profile DB、取消与双重校验 | TC-AUTH |
| 路径穿越／覆盖文件 | 曲名、下载名、导入清单、符号链接 | canonical path 验证、受控目标、冲突确认 | TC-DOWNLOAD/LOCAL |
| 远程文本／图片攻击 | 评论、歌词、封面、元数据 | 纯文本、大小／像素上限、无任意脚本、解码器更新 | TC-SECURITY |
| 非预期网络访问 | 返回 URL、重定向、分享链接 | scheme/host 策略、拒绝本地敏感地址、不转发凭据 | TC-API |
| 重放／重复写 | 超时自动重试 | 操作安全分类、对账、不确定结果状态 | TC-SYNC |
| 供应链攻击 | Qt 插件、依赖下载、更新包 | 固定版本和哈希、签名、受控插件路径、SBOM | TC-PACKAGE |
| 资源耗尽 | 大响应、海量文件、坏歌词、解压炸弹 | 有界队列、体积限制、取消、解析预算 | TC-FAILURE |

不承诺抵御已经控制同一 Linux 用户账号／调试进程的攻击者；密钥环不能让恶意同用户程序永远读不到内存中的会话。用户下载文件是否加密由资源格式和授权决定，不自行宣称整库加密。

## 2. 凭据与认证材料

- Cookie、令牌、CSRF、二维码挑战材料、临时签名 URL按敏感等级处理。
- 会话持久化仅允许系统密钥环，QtKeychain 的不安全明文 fallback 必须禁用并测试。
- 密钥环拒绝／不可用：提示本次会话模式，不引导把 Cookie 粘进配置文件。
- 密码若某种官方流程确实需要，只短期驻留、不持久化；优先采用已验证的扫码方式。
- 登出清理内存和密钥环，账号切换创建新隔离上下文。
- 不在客户端二进制中嵌入个人账号、开发者 Cookie、私钥或可复用服务凭据。
- 内存清除可尽力执行，但 C++/Qt 字符串隐式共享可能产生副本；不能以一次 memset 宣称秘密完全不可恢复。

## 3. 网络与协议安全

1. 正常验证 TLS 证书和主机名；不得调用忽略所有 sslErrors 的通用分支。
2. 官方端点登记为受控集合，不把用户输入拼成请求主机。证书 pinning 不是首版默认，以免正常轮换导致服务中断；若未来采用，须设计备份 pin 与恢复。
3. 重定向设次数上限（初值 5），拒绝 HTTPS 降级和凭据跨域扩散；必要新 CDN 域通过审查更新。
4. URL 验证包括完整域边界、国际化域名、scheme、端口和本地／链路本地地址，不能用 `host.contains("netease")`。
5. 官方 API、图片、下载、媒体播放分离身份策略；媒体库不会自动继承 API 网络安全设置。
6. 如果 Qt 后端不能强制某项所需请求头／重定向策略，则不能将敏感头直接交给不受控链路；M0 选择可验证的传输方案或后端。
7. 签名算法依契约实现并用向量测试，使用成熟密码库；协议中的公开常量不等于秘密。
8. 不在 URL 查询串中额外拼装应用自己的敏感诊断参数；协议不得不包含的字段必须在日志层整体隐藏。

## 4. 不可信内容限制

初始限制由实际样本校准，并对合法批量场景分块而非无限放大：

| 内容 | 初始上限建议 |
| --- | --- |
| 常规 API JSON 单响应 | 8 MiB，少量特殊 operation 单独登记 |
| 单首歌词 | 2 MiB，行／词数量与时间戳另设界限 |
| 封面网络载荷 | 10 MiB |
| 解码后图片 | 最多 16 百万像素，再按展示尺寸采样 |
| IPC／外部 URI 参数 | 16 KiB |
| 导入清单 | 10 MiB，逐项验证和数量上限 |

压缩响应同时限制解压后大小。图片尺寸限制要尽量在全量分配前检查；损坏或超限资源回退占位。远程 SVG 若没有明确必要性不启用；评论和歌词使用纯文本或白名单富文本，不执行脚本、不自动打开链接。

下载文件名去除路径分隔符、控制字符和平台危险名称；目录写入防符号链接越界，覆盖已有文件需确认。应用不会因远程元数据要求而执行外部命令。

## 5. 隐私与日志

默认无使用行为遥测、无广告追踪、无后台上传本地曲库。官方 API 的业务必需请求和播放报告在隐私说明中列出，与 Cirrus 自建统计明确区分。

推荐日志字段：timestamp、level、component、eventName、requestId、耗时、错误类别、协议版本、状态迁移。禁止直接记录：Cookie、令牌、密码、签名参数、完整响应正文、私人歌单内容、评论草稿、完整媒体 URL、本地绝对路径。

搜索词、歌曲历史和账号标识也属于用户信息，默认不记日志；必要调试用临时散列／长度／计数。脱敏应在采集边界进行，不能只在 UI 导出时替换。

- 用户主动开启诊断有清晰时限和关闭入口。
- 日志轮转并设总预算，参考 09。
- 诊断包列明文件，提供预览和删减，明确是否包含环境／设备信息；不自动上传。
- 原始 core dump 可能含凭据，不纳入普通自动报告。崩溃上传如未来引入须独立同意和清理方案。
- 允许清除搜索历史、播放历史和缓存；清理按钮明确本地／官方数据范围。

## 6. 内容授权与品牌

- 用实际账号权限访问歌曲和音质，区分试听、完整播放、下载、离线可用和云盘。
- 不实现付费绕过、DRM 解密、规避地域限制或未授权批量抓取。
- 用户提供的接口资料作为实现依据；对公开分发仍记录实际使用的协议与依赖条件，不编造“官方授权合作”关系。
- 产品显示 Cirrus 品牌及第三方客户端说明，不使用可能误导为官方的软件名称、商标或发布文案。
- Apple Music 只作为设计参考，不复制受限图标、字体、截图和专属资源。

这不要求用户自行配置接口，也不改变既定官方 API 直连架构；它约束的是内容能力如何如实呈现。

## 7. 开源依赖与软件许可

正式发布前必须明确 Cirrus 自身许可证，建议维护者在开源分发模式、潜在贡献和依赖条件之间做选择。本文不擅自添加 LICENSE。

发布审查至少覆盖：Qt 各使用模块、FFmpeg 的实际构建配置、OpenSSL、QtKeychain、TagLib（若引入）、图标／字体和音视频测试素材。

- Qt 有多种许可，不能简单写成“用了 Qt 所以必须闭源／必须开源”。
- 若选择 LGPL 路径，核对动态链接、用户替换库、通知、许可文本、源代码提供等适用义务；商业许可是另一条路径。
- FFmpeg 或 libmpv 的实际许可取决于构建选项和依赖，不能只看库名。
- 单独分发 Qt 插件、codec 和系统库会引入额外义务，纳入 SBOM 和 attribution。
- CI 生成依赖版本／哈希／许可清单，发现未知许可证禁止正式发布。

## 8. 更新与漏洞处理

Flatpak 优先使用平台更新机制；AppImage 首版可只做检查并引导可信下载，不急于自实现静默更新器。若实现自动更新，必须验证签名、目标版本、平台架构、完整性和回滚策略，不只校验同一不可信站点给的 SHA-256。

维护者提供安全问题报告渠道；正式仓库尚未确定时列为发布阻塞项，不虚构邮箱。漏洞处理记录影响版本、缓解措施、修复和发布证据。重要安全修复应优先于非必要视觉增强。

# 后端移植顺序与验收门禁

范围与阶段以[总路线图](../14-roadmap-and-backlog.md)为准。静态审计已完成；C++ 的 form／默认路由和 Qt Test 已起步，见[实现记录](native-foundation.md)，但尚未完成下面任一整阶段。

## M1：公共协议 → 登录／会话

- 建立 Network、Protocol、Session 和 DTO 测试边界，应用层不依赖上游包装格式。
- 先证明 URL 改写、form/JSON、weapi/eapi、响应解码的字节行为，再接 XEAPI key/session/加密响应。
- 匿名启动、Cookie 域策略、设备 profile、密钥更新均有失败状态。
- QR key／本地二维码 URL／轮询分离；凭证只进入安全存储或内存。
- 业务错误、HTTP 错误、取消、解析错误和未知结果分别建模。

**退出门禁**：离线向量、损坏数据、尺寸限制、取消和 epoch 测试通过；授权环境下登录／恢复／退出验证通过。v2 token 不在本阶段强行引入浏览器依赖。

## M2：音乐查询、播放、日推与 FM

顺序：搜索／歌曲／歌词 → 专辑／艺人／歌单 → 首页／日推／FM／个人库／评论读取。

每个 operation 至少登记：逻辑路径＋实际主机 profile、协议、参数类型和约束、登录要求、响应 envelope、DTO 与分页、限流／缓存／重试语义及脱敏 fixture。当前 JSON 的源码观察只能作为起点。

- 先验证真实官方 URL，再冻结 QMediaPlayer 默认后端。
- 查询返回缺字段、超大 ID、空页、部分曲目不可播、URL 到期均有测试。
- 日推不是普通歌单；FM 是续批会话；混合搜索／首页／评论严格过滤禁入资源。
- 用 CLI／测试 harness 跑首听链路，不做 UI 页面。

**退出门禁**：关键读取与音源真实验证、队列／歌词／连续播放测试、账号缓存隔离完成。

## M3：写操作与一起听

- 歌单创建／修改／增删／排序、歌曲喜欢、艺人／专辑收藏、评论写和播放上报分别定义成功判定及对账方式。
- 所有写默认不自动重放。使用本地操作 ID 不代表官方支持幂等键。
- 歌单收藏的 v2 token 先调查原生路径；需要新增运行组件时征求维护者同意。
- 一起听先补接收链与同步契约，再做状态机和双账号测试；不虚构 WebSocket 或固定心跳间隔。

**退出门禁**：超时未知结果、部分成功、重复触发、权限失效和换号测试通过；一起听有完整双端证据。未达门禁的能力须保留为受限并明确决策，不能勾选完成。

## M4：下载、云盘与后端稳定性

下载 URL／权限独立于播放；NOS 上传流式传输，令牌不跨域泄露；云盘提交／发布有恢复记录。补齐本地扫描、数据库迁移、恢复、非视觉 Linux 服务和发布依赖 PoC。

**退出门禁**：授权、文件完整性、取消／磁盘满／崩溃恢复、长期播放及秘密扫描通过。评审剩余缺口后冻结供 UI 使用的应用层接口。

## M5：最后实现 UI

此时才启动自有控件、Gallery、页面、ViewModels、沉浸播放与可访问性工作。UI 不接触官方 DTO、Cookie 或 crypto 参数；不得为页面方便反向改成通用 API 透传。

## 不包含在当前交付中的证明

- 未进行真实官方 API、Cookie、会员、下载或双账号调用。
- 已有 weapi/eapi C++ 编码与离线合成向量，但没有官方实测兼容证明；XEAPI 尚未实现。
- 未认定上游所有模块均可运行，未确认所有响应字段。
- 未进行 UI／交互／Wayland 功能验收。

这些缺口是明确的后续任务，不影响本轮“固定来源、划定范围、揭示依赖”的审计交付。

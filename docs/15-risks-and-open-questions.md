# 15 · 风险登记与待确认事项

> 状态：提案。问题清单用于安排验证，不要求一次回答全部问题；有安全默认值的项目可以继续，不应以提问代替开发准备。

## 1. 已明确的项目约束

以下不是待讨论项：

- 产品名 Cirrus，工程名 CirrusMusic。
- 使用 Qt Quick/QML；客户端后端采用与 Qt 配套的 C++ 方案。
- 自有控件视觉体系，不能把默认 Qt 外观直接作为成品。
- 沉浸播放页参考 Apple Music 风格；先完成后端，再开始 UI。
- **直接使用网易云官方 API，由 Cirrus 内置适配，用户无需配置接口或部署任何服务。**
- 参考 api-enhanced 的固定源码，自行用 C++ 实现；不运行 Node 服务。已完成静态审计，真实契约仍需验证。
- 包含每日推荐歌曲、私人 FM、一起听，并经维护者新增播客／声音消费端读取和播放；仍排除视频、云贝、动态、云小编和创作者管理工作台。新搜索／独立ID的有限公开证据见[实体搜索](api/entity-search-reads.md)，不能证明全站完整性、工作台权限或声音播放权益。

## 4. 决策记录格式

每个问题关闭时填：决定、依据（接口样例／官方资料／实测报告）、负责人、日期、影响需求、影响 ADR、实施任务。仅回复“应该可以”不算关闭可行性问题；涉及体验偏好的问题可以由维护者明确拍板。

风险复查节点：M0 完成、每次 API 契约改变、播放器／Qt 升级、数据库迁移、权限增加、发布前。出现新风险先登记具体失败方式，而不是泛写“有一定风险”。

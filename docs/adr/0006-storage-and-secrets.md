# ADR-0006 · SQLite、profile 隔离与系统密钥环

- 日期：2026-09-26
- 状态：Proposed
- 负责人：存储／安全

## 背景

客户端需要队列、历史、快照、下载任务与设置，必须支持崩溃恢复及多账号隔离。Cookie 不能与普通数据混存。

## 决策

Qt SQL + SQLite 存结构化数据，公共元数据库与每个 profile 的私有库分离；DB worker 单线程拥有连接，使用事务、版本化迁移和一致备份。QSettings 仅保存非敏感偏好；密钥环通过 QtKeychain 访问，禁用明文 fallback。

元数据／封面缓存、用户下载、临时文件分别管理。播放 URL 不持久化。远程写默认在线确认，未知结果对账，不先做通用离线 outbox。

## 备选

- 所有内容写 JSON：关系、事务和迁移成本高。
- 单库仅靠散落 profile 条件过滤：容易遗漏，选择物理命名空间加强边界。
- 本机 Redis／数据库服务器：无必要运行依赖。
- Cookie 写配置或自制可逆“加密”：不满足凭据保护要求。

## 后果

多个 DB 连接仍由同一 worker 管理，跨库没有天然事务；需要的公开元数据以私有快照引用，不依赖跨库 FK。普通库不因此自动加密，隐私说明必须诚实。

## 验证与复议

M1/M2 验证换号、WAL 备份、迁移中断、密钥环不可用；M4 验证下载文件／DB 崩溃窗口。大规模本地库性能或新的强加密需求出现时再评审，不提前引入复杂同步系统。
